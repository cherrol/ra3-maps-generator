# 地形与斜坡

本地目录与 CLI id 使用 [系列映射](../../../docs/九州大地命名.md) 中的真实地形名，例如 `maps/陕西/`、`--map 陕西`。同版制作资料在 `assets/陕西/<生成发布名+版本>/`，成品目录在 `dist/陕西/<生成发布名+版本>/`，源 ZIP 使用生成文件名，如 `dist/陕西/[CHAI]千壑横原T0.7.8.zip`。原型或生成名的预览入口都定位真实目录，标题和包内游戏文件继续保留生成名。

新图使用配方启用的声明式蓝图与显式布局；当前读取本图 `LAYERS` 指定文件（默认 `layers.npz`，现有四图为 `histories/v11/layers.npz`）中的 `base_z`（GRID×GRID）和 `z_scale`，公共预览 `terrain.npz` 需先整理为该输入，不能直接交给 build。DEM/底图作为参考，不重新自动搜索布局。冻结成品以完整原生高度、材质及位图为准，不从旧蓝图重挖。层高、水面与海底值读取本图配方和来源，不把某图高度写成全局常数。

## 坐标与预览

本图 `coordinates::Frame` 记录宽高、边框、格长与高度比例。全图格原点在西北，X 东/Y 南；世界坐标 X 东/Y 北，由同一 Frame 正逆转换。内部高度、布局和预览保持北朝上；原生高度/位图和 TGA 按各自存储格式转换，不根据海在哪一半猜轴向或再次翻转。见 [坐标公式](../../../docs/map_coordinates.md)。

公共预览按 [预览标准](../../../docs/terrain_preview.md) 处理整张紧包主体的矩形范围，主体地理边界外但游戏框内的地形同样分层。可玩设计宽高均不超过 800 格、至少一边为 800，短边取最近 8 格倍数；四周默认 20 格制作边框。PNG 图例/留白不计入格数。

保留 2–5 个实际陆地层级，不强凑五层；碎层合并，高原主要保留可玩台地，最高层主要保留突出山脊/峰顶。海洋与大湖泊按本次参考和水域策略保留，不用河流线或负高程替代海洋。高程入口缺少 `water_mask` 时实际回退到 `elevation_m <= 0`；要求真实水域时先由 Codex 准备可靠轮廓掩码再核对。基础图为 `source.png`、`preview.png`、`preview--line.png`，可选中心图单独生成。设计帧保存于 `data/terrain-preview/coordinate-system.json`，不覆盖已有可玩帧。

预览水域避免细长条、窄颈分叉和零散碎块。相邻水体或同一水库的支汊优先就近填合、圆整为宽阔且闭合的连片水面；无法合理合并的细小水域并入附近实际相邻陆地层，整理局部层界。原始高程、边界与来源水域保留，数值规则按本图尺度确定，同步重绘基础图和已有中心图；见 [游戏水域整理](../../../docs/terrain_preview.md#游戏水域整理)。

水陆两侧一并整理：伸入水域的细长陆地、窄颈半岛和尖细尾部也须就近收拢、拓宽或并入水域，保留宽阔主体。小岛和小水域的整圈边界均须采用连续可双向通行的层间过渡，使所有边界位置都可通向相邻层级，不能只留几个坡口或单一出口。按实际整圈边界逐段核对过渡宽度、坡度及通行；纯预览记录全周过渡设计，推进可玩制作时落实到高度与导航，不能仅凭色块接触判为通行通过。

## 坡形、通行和保护区

坡道位置、方向、连接层及宽度以布局和实际原生地形为准，不恢复旧自动搜坡规则。`RAMP_PROFILE` 缺省为 `mountain`，`legacy` 仅用于历史复现；保持稳定坡面、平缓端口和完整声明宽度，坡面材质接回实际上下台地，不铺灰白矩形面或孤立短土斑。

资源避让同时覆盖坡面全宽、声明端口及沿轴双向延伸区，并检查完整矿场/建筑占地。公共 `ramp_clearance` 当前默认两端延伸 25 格、净距 8 格，读取生效策略，不按坡心距离代替。保护基地核心、矿盘、资源通路、建筑及赠送主备完整占地；不为凑坡形擅自挪矿或压平别层。旧成品问题留档，新增/恶化项拦截。见 [坡口避让](../../../docs/ramp_clearance.md)。

已有成品用最新 ZIP 执行 `polish-ramps --map <id> --bump <源ZIP>`；仅整理表面用 `polish-ramp-surfaces --map <id> --bump <源ZIP>`，移动/增设用 `relocate-ramps --map <id> --bump <源ZIP> <方案JSON>`。表面整理保持高度及导航位图；坡形修改按实际范围检查差异及原有路线。几何不能只改布局参数而不改原生地形。见 [山地斜坡](../../../docs/mountain_ramps.md)。

## 材质与封装

新蓝图构建默认 `TEXTURE_PROFILE: classic-natural`，使用当前五层主纹理及混合规则；`legacy` 仅历史复现。冻结成品保留来源材质，显式更新用 `polish-textures`，不覆盖已定稿几何。当前材质和层高映射见 [纹理规则](../../../docs/terrain_texture_rules.md)。

原生材质清单、XML、图集和脚本资产声明保持成套，新增材质同步声明后校验再保存。不要删除资源清单规避加载问题。封装细则见 [地形封装](../../../docs/terrain_package_fix.md)，版本及采用来源见 `ra3-pipeline`。生产流程不包含实机检查步骤。

## 蓝图与版本资料

蓝图输入由 `LAYERS` 选择，默认 `layers.npz`；根 `layers.npz` 始终与当前选定定稿蓝图原件逐字节一致，不从 `.map` 回读生成。四张现有图显式使用 `histories/v11/layers.npz`，同版历史布局在 `histories/v11/layout.json`；冻结生产来源仍为 `authoring/source.zip`。预览 `terrain.npz` 不直接替代构建蓝图。

蓝图版本按本图 `histories/v1/`、`histories/v2/`、`histories/v3/`、`histories/v11/` 保存，成品版本资料也保存在 `histories/T<版本>/`，各版编号对照为 `histories/<T版本>/coordinate-id-map.json`。编辑方案、蓝图/布局/配置/基准快照和高程材质配套按版本一起归档，活动引用同步新路径；原始游戏输入 ZIP 保留原文件名，制作源快照使用 `histories/T<版本>/source.zip`，所有 ZIP 字节保持。广东无法确认版本的旧 `layers.npz` 保留于 `histories/legacy/layers.npz`，另建所选版本根镜像。详见 [蓝图与版本资料](../../../docs/blueprint_versions.md)，不改变旧 `v11_*` 开关的算法语义。
