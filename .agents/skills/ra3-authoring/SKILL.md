# 从资料到预览与可玩地图

先按[公共约束总表](../../../docs/map_rules.md)确定本轮是纯预览、新图还是完整原生源编辑；目录、CLI id 与游戏展示名查[系列命名](../../../docs/九州大地命名.md)。只处理本轮范围，完整来源不豁免当前严格规则。

## 纯地形预览

识别高程、图片、轮廓与水域来源，按[公共预览流程](../../../docs/terrain_preview.md)准备输入。仅有图片时按视觉蓝图判读，不把目测当测量高程；需要生成或编辑位图时使用 imagegen。处理整个游戏矩形，包含主体边界外的真实地形；设计 Frame 与可玩 Frame 分开，PNG 图例不计入地形格数。

设计中落实[小水域单层包裹](../../../docs/terrain_preview.md#小水域的单层包裹)、全周水陆过渡，以及[交战路线与伸入地形整理](../../../docs/terrain_preview.md#交战路线与伸入地形整理)：跨层小水域按调整前最多接岸层归并岸边，通路不足拓宽、细长伸入不足就近归并，全部赠送占地避开伸入区域。同步实际数组和参考输入，不能只改图或策略；交战布局未定时记录预留与待验范围。

按[地形交接规范](../../../docs/terrain_transitions.md)同时预留坡面、层界、岸线及其交汇处的连续过渡空间，记录可通行与阻断边界。参考系列样本用于比较衔接做法，不能直接套用其高度、宽度、材质或局部断岸；纯预览只交付设计预检，实际几何、材质与导航留待可玩制作回读。

```sh
cargo run --release --locked -- terrain-preview <原型或图名> <高程NPZ>
cargo run --release --locked -- terrain-preview-centers <原型或图名>
```

交付 `maps/<id>/source.png`、`preview.png`、`preview--line.png`；有可靠 WGS84 中心资料及地理范围时另出 `preview--center--line.png`，不猜中心坐标。原始资料、参数与设计帧放本图 `data/terrain-preview/`。纯预览到此交付，不创建玩法布局、递增版本或打包安装。

## 推进可玩制作

按[Rust 配方](../../../docs/rust_migration.md)准备 `LAYERS` 与显式 `LAYOUT`；预览缓存须整理成构建输入，不能直接当蓝图。已有成品读取 `COORDINATE_PIPELINE` 引用的完整 ZIP、CRC 与布局，保留本轮无关的原生地形、身份及脚本，不从旧预览重建覆盖定稿。位置统一通过本图[Frame](../../../docs/map_coordinates.md)换算。

按[路线与布矿顺序](../../../docs/resource_distribution.md#对位进攻路线与沿路布矿)先确定对位基地间的直接主路、跨层坡道及完整引道，再布矿。[斜坡优先于矿](../../../docs/ramp_clearance.md#斜坡优先级与冲突处理)；冲突交给资源技能退让矿位，不为保矿削改、缩窄或挪动合理坡道。开局两矿移动后仍须满足[完整出生组](../../../docs/spawn_placement.md)，外围矿沿实际主次路线分散；坡轴按真实层界确定。

将预览中的交接设计整理为实际构建输入，先由 ra3-terrain 联合处理坡口、层界与岸线交汇，再安排完整玩法占地及材质收边；不把分别通过的三段边界视为交汇处已连续。按[地形交接验收](../../../docs/map_acceptance.md#地形交接如何验)保留同版剖面、导航及视觉证据。

出生组与固定 AI 用 ra3-spawns，资源计划用 ra3-resources，层界、岸线、坡道及纹理用 ra3-terrain，构建、版本与冻结源用 ra3-pipeline。布局阶段即执行[建筑四向规范](../../../docs/production_placement_fix.md#所有建筑的四向约束)，覆盖全部预置、脚本控制建筑及矿脉 `OreNode`，朝向变化联动完整占地与通路。

## 交付衔接

证据、适用范围、状态与交付判定统一按[公共地图交付验收](../../../docs/map_acceptance.md)。纯预览核对设计空间；可玩定稿将专业结果交给 ra3-pipeline 汇总原生回读、独立验收、版本与冻结源。
