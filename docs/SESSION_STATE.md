## 3. 已确立的规则（都在 spec 文档 §19.x）

- 出生点 8 个：**西 4（P1–P4）对东 4（P5–P8，P7/P8 固定 AI）**，格坐标见上表。不压平 80×80。水上基地不要求陆路连通
- 矿脉：每玩家 4 个（近 2 在 44~62 格且恰好 2 个 + 周边 2）+ 中路争夺 6 个，沿东西向约 20%~80% 铺开
- 矿：每个基地旁 2 个，朝基地。其余矿每名玩家 4 个，按总数撒开，陆地和水面各一半，矿口朝开阔处
- 水域达到可玩区 20% 时，在双方交汇点附近的水面放 1 个船厂。机场、车库、医院在陆地，各 1~2 个。精兵学院和哨站各 2 个，从交汇中心往两侧分开。建筑彼此隔开
- 油井：每个基地附近 1 个，跟着出生点（水上基地落附近水面，陆上基地落附近陆地），其余按地级市摆在城市里。落点避开层界、岸线、斜坡和不可通行
- 矿场可建造性（T1.9.5）：核心盘 r12 高差≤10、矿口半圆盘 r16 高差≤12、离图边≥14；不可通行豁免打在**最终矿位**
- 建筑/资源落点必须平整（坡度<2.5）或在水域
- 以上四项加上斜坡、轴向，由 `python tools\accept.py` 一次验收；不过则构建失败
- 桥只在**细长水域**（水面宽 ≤46 格）上架，桥段必须压在水面上
- 城市：水泥路 30 格 + 草地；每城 1~2 个房子；预览标 `Player1-8` + 资源逐个编号
- 平台默认**陡坎**；海域拉平；西南/西侧全陆地（保留河流）
- 斜坡（T1.9.8）：相接的层与层、水与陆各 1 条，交界长则 2–3 条，共 16 条，边长 28。上坡朝向中心或资源。沿坡约 1.2（水陆）或 3.6–3.8（层间），端缝 ≤12，横向 ≤10。斜坡外的层界和水岸不可通行。不再用 `ramps.json` 的矩形，也不再从水上出生点另铺堤道。
- 层级纹理（T1.9.2）：按陆地层级分草皮家族（配置 `LAYER_TEX`：212 平原 CapeCod 亮绿 / 280 Golf / 350 Geneva 深绿 / 420 CapeCod 黄绿），同层视觉一致、层间相近可分辨；沙滩/城市/斜坡/岩壁优先于分层

## 4b. 层规则（本轮成果，spec §19.33）

真地图现在的分层是「边界平滑 r5×1 + 删孤立块(350<1600 / 420<2400 降一级) + 第一遍连片(350 闭运算 r40、280 r10、420 r10)
+ 第二遍删块(350<5000) + 收尾平滑 r4」。与 v11 目标逐格一致率 **0.844**、二层 IoU **0.675**（v10 基线 0.788 / 0.483）。

**关键认知**：v11 是在 v10 图层上**手改**出来的，不是 DEM 直接切层（DEM 切层族一致率只有 0.648）。
"连片"的正解是**删孤立块**（整块降一级）而不是把缝隙填平 —— 单纯膨胀式连片一致率只有 0.58，
而且它是把边界整体外推，语义不对。

## 6. 踩过的坑（务必先看）

- **坐标轴（务必先做锚定测试，别猜）**：`terrain.npz` 的 row 0 是**北**。
  **T1.8.7 根因实锤**：v11 时代起地形（raw，row0=北）与 `Geo.to_cell`（旧公式 `y=oy+(lat-lat0)*sy`，
  row0=南）就是**两个相反的帧**。症状"边界线/城市与地形南北相反"：北海市被放到内陆 630 格、
  省界红线的海岸弧悬在海上。旧验收脚本（`final_axis_accept.py` 的"海在哪一半"、IoU）测不出，
  因为它们只检查地形自身的朝向，从不把 geo 派生物与地形做**交叉锚定**。
  修复：`to_cell` 改为 `y = oy + (lat1-lat)*sy`（一行），下游全部自动对齐；
  同步修了 `make_preview` 城市标注（翻 y）、`fetch_dem`、`compute_bridges` 方向、`lat_row` 反算。
  **有效判据（有区分度的地理锚点）**：① 沿海城市（北海/钦州/防城港）距海应 < 50 格；
  ② `make_mask()` vs `land` 的 IoU 同帧 0.82 / 翻帧 0.63；③ dem 同帧取海拔：百色 510m > 桂林 38m。
- `terrain_preview.png` 渲染时做 `np.flipud`（把 row 0 放底部），与数据行序相反，看标注意别弄反
- TGA 是自下而上的格式，写 `_art.tga` 时另有一次翻转，别与上面的规则混淆
- 改朝向后要同步的 6 个产物：高度图/对象、`_art.tga`、`preview.png`、`build_view.png`、
  `terrain_preview.png`、`passability_preview.png`（后两者含标注 y 也要跟着翻）
- **死代码陷阱**：高度场若在别处**重新内联**未掩码的表达式，山体掩码（开运算/keep_largest）全失效
  → 症状"满地图零散小山、改参数没反应"。同一段公式只能有一处
- **同一步骤可能有多处赋值**：`sw_plain` 曾有两处，后面那处把前面的覆盖（西南岸线一直不生效）
- **`ensure_count` 只补不删**：模板多余矿物件会被"撒到外圈"，绕过全部约束 → 必须显式 `objs.remove`
- **`resolve` 放不下就返回空**，不再把间距乘 0.92，也不再换更宽的掩码
- **高山层必须放函数末尾**并避开出生点/矿区平台，否则会穿透基地（P1~P4 曾出现 76~156 落差）
- **归属判定别看对象顺序**（保存后顺序会变），要按"离哪个出生点最近"归属
- PowerShell 内联 Python 的引号极易被吞 → **优先用 edit 工具或写 .py 补丁文件**
- `--bump` 先递增版本号；构建失败会把 `version.json` 滚回，并删掉这次新产生的版本目录
- **沙箱里不能用 `multiprocessing`**（命名管道被拒，WinError 5）→ 并行要用多个后台进程/Start-Job 分片
- `check_passability.py` 原先自己用经纬度算出生点，百色纬度 26.02×V_STRETCH 1.4 → y=1062 越界崩溃；
  已改为**优先用 terrain.npz 里吸附后的格坐标**并夹进可玩区
- **轴向自查方法（抄这个，别靠记忆）**：把 `terrain.npz['land']` 与 `geo.make_mask()` 相减应为零；
  再用 `geo.to_cell` 算桂林/北海的格坐标，取 `z[y,x]` 看是否落在陆地/海边 —— 一次就能判定行 0 在南还是在北
