# Rust 迁移与数据配方

本分支将可执行工具链迁为原生 Rust；原来的 Python 配方不再执行。四张现有地图的定稿高度、出生点、资源、装饰、公共脚本、固定 AI 和可选进攻规则均在迁移时导出，并由回归校验值约束。

本文的分层蓝图重建说明描述迁移后的新图路径与历史复现。四张现有地图已启用 `COORDINATE_PIPELINE`，当前构建读取各自 `authoring/source.zip` 的完整原生成品与 `authoring/layout.json`，保留实际高度、材质、位图和脚本；`histories/v11/layout.json`、`histories/v11/layers.npz` 作为历史重建输入，不覆盖冻结定稿成品。现有图的坐标编辑、空间增量验收及采用新来源步骤见 [通用坐标制作流水](coordinate_pipeline.md)。

## 从过程式配方到声明式数据

原构建在读取 `config.py` 后自动搜索斜坡和资源落点。迁移时改为显式布局：`layout.json` 保存那次搜索的定稿结果，四图现归档为 `histories/v11/layout.json`。未启用冻结成品模式的新图由 Rust 从配方指定的分层蓝图重新计算层高、海深、斜坡剖面、登陆岸、平台、纹理和通行/建造位图，并组装所有对象与脚本。

新蓝图路径改变布局应修改配方指定的 `layout.json`；冻结成品路径的受控坐标修改使用 `authoring/layout.json`，改变坡道几何等内容应走原生成品增量编辑器。旧版自动搜索、DEM 下载、底图抓取和一次性逆向研究脚本没有作为 Python 兼容层保留；制作前预览改用 [公共地形预览](terrain_preview.md)，由 `terrain-preview` 接收当次提供的高程资料，参考图片则按制作技能解释为设计蓝图，不自动套用某张地图的数据源；如需研究其历史实现，可查看迁移前的 Git 历史。已有 DEM/地理输入文件保留，新蓝图路径直接读取配方指定的分层输入。

## config.json

`SCHEMA_VERSION` 为 1。核心字段：

| 字段 | 用途 |
|---|---|
| `MAP_NAME` / `PUBLISH_NAME` | 游戏名称前缀 / 可选发布名称前缀；不决定本地目录 |
| `RESOURCE_ID_SEED` | 可选 uint32，固定资源命名空间；目录和 CLI 改名不改变资源身份 |
| `GRID` / `GRID_HEIGHT` / `BORDER` / `CELL` | 全图宽度 / 可选高度（默认等于宽度） / 边框格数 / 世界单位换算 |
| `Z_SCALE` / `WATER_Z` | uint16 高程换算 / 水面高度 |
| `TEMPLATE` | `templates/` 下的地图骨架 |
| `RULESET` | `templates/rules/<RULESET>.json` 脚本与阵营规则 |
| `LAYERS` | 地图目录内的蓝图 NPZ，默认 `layers.npz`；四张现有图显式为 `histories/v11/layers.npz` |
| `LAYOUT` | 地图目录内的布局 JSON，默认 `layout.json`；四图历史蓝图配对为 `histories/v11/layout.json` |
| `COORDINATE_PIPELINE` | 可选完整成品来源、可编辑布局、空间检查基准与局部策略；启用后走冻结成品路径 |
| `RESOURCE_DISTRIBUTION` | 新图及重新布矿必备的本图矿位阶段与路线计划；继承公共 6 矿/位、家区 3 矿规则 |
| `SPAWN_PLACEMENT` | 可选出生点策略对象；显式配置时要求严格零问题，缺省新图严格、冻结源逐项继承原问题并拦截新增/恶化 |
| `HEIGHT_PRESET` / `LAYER_M` | 标准高度预设 / 陆地层高 |
| `TEX_SET` / `LAYER_TEX` | 纹理资源与层纹理映射 |
| `MAP_STR_*` / `PREVIEW_*` | 游戏文本与预览文案 |
| `TERRAIN` | 蓝图量化、海深、斜坡羽化、登陆岸和出生平台参数 |

`GRID` 和可选 `GRID_HEIGHT` 须为 8 的倍数，边框必须小于两边各自的一半。蓝图 `base_z` 按 `[GRID_HEIGHT, GRID]` 保存，未配置高度时仍为方形。地图 id 使用真实地形名（如 `陕西`）；制作资料和成品分别位于 `assets/<id>/<生成发布名+版本>/`、`dist/<id>/<生成发布名+版本>/`，ZIP 文件名与游戏内容继续使用生成发布名。地图 id、发布名和配方路径必须留在工程范围内。当前原生地形路径使用 `use_v11_layers: true` 与 `v11_plain: true`；已包含斜坡的定稿图使用 `v11_baked: true`。

蓝图文件按版本目录保存；根 `layers.npz` 与当前选定的定稿蓝图逐字节一致，不由 `.map` 回读或重新量化生成。版本切换需核对 `LAYERS`、对应 `LAYOUT` 及根镜像；冻结成品继续读取完整 `authoring/source.zip`。完整目录约定见 [蓝图与版本资料](blueprint_versions.md)。

同一张地图改目录或 CLI 名称时保留 `RESOURCE_ID_SEED`；复制配方创建另一张地图时删除该字段，由新的 id 派生资源命名空间。

新蓝图路径的纹理噪声使用与旧实现相同的 MT19937 取样和种子，纹理与地表装饰由 Rust 重新生成。冻结成品路径则读取并保留来源原生纹理与位图，不自动套用新的纹理规则。

## layout.json

所有坐标均为全图格坐标，x 向东、y 向南。下列字段说明用于新蓝图路径的布局；`objects` 定义实际游戏对象，其余集合用于地形构造与验收，调整资源或出生点时须同步修改对应集合与对象。冻结成品路径以 `authoring/layout.json` 的原生对象身份与顺序为准，从实际对象派生矿位等分类清单，无需手动重复同步；该路径不允许只改 `ramps` 参数而不修改原生高度。

- `base_cells`：按人类 1–6、固定 AI 7–8 排列的最终出生点；对置侧别及与两矿同面空间由[公共出生点验收](spawn_placement.md)检查。
- `base_pad_cells`：可选的场地铺平中心。水上出生点在铺平后纠偏时，用它保留先前铺平位置；缺省取 `base_cells`。
- `ore_cells` / `ore_angles`：最终矿位和内部坐标系的矿口角度。对象中的游戏朝向使用相反 y 轴。
- `derrick_cells`、`post_cells`、`garage_cells` 等：资源和中立建筑位置。
- `city_cells`：定稿城市纹理中心。
- `ramps`：斜坡中心、矩形尺寸、低/高层、上坡向量；可编辑后重新构建其剖面。
- `objects`：类型、版本、格坐标、角度、道路类型和有类型的属性表。bool/int/float/ASCII/Unicode/unknown 属性分别保留其磁盘类型。

斜坡实际坡面宽度不得小于 20 格，羽化坡肩不计入宽度。每条斜坡只连接两个台地层，坡面及衔接范围须避开第三层台地；两端不要求层号相邻。例如第一层与第三层直接相接时可以开坡，但不能让同一条坡穿过第一、第二、第三层台地。坡面插值过程中经过第二层的数值高度不算第三层台地。该规则也适用于 `face` 布局，优先于旧说明中的“只连接相邻两层”。局部斜坡优化按实际全宽检查并行车道、两端衔接和横向高差。

新蓝图构建默认使用 `TEXTURE_PROFILE: "classic-natural"`，缺省亦采用此值。当前采用用户确认的五层主纹理：`Grass_NewYork01`、`Grass_MtRush04`、`Grass_CapeCod05`、`Rock_Yucatan03`、`Rock_Iceland02`；前三层保留原有变体和 T2.2.9 自然分布规则。新蓝图构建在 `map` 阶段自动调用与 `polish-textures <成品ZIP> --map <id> --bump` 相同的选材和混合函数；冻结成品构建保留来源材质，应用当前规则需显式运行后者。旧迁移纹理可用 `TEXTURE_PROFILE: "legacy"` 复现，历史回归测试显式使用此配置。其他配置值会在版本递增前报错。

此美化允许同层使用草地、土壤的少量变体，替代旧 mountain 预设的整层单纹理。纹理后处理不更改高度、对象、脚本、已有材质编号或通行/建造位图；缺失材质追加登记，并同步加载声明；已有成品通过 `polish-textures` 保留局部斜坡与实际布局快照。材质示意图不代替游戏内效果验收。规则详见 [通用纹理规则](terrain_texture_rules.md)。

选材必须查看原始 diffuse、normal 贴图与真实渲染，不能仅按 `Grass` 名称或示意颜色判断。已从本机原版 `Terrain.big`/`TerrainFix.big` 解码确认：`Grass_CapeCod01/03/07`、`Grass_Golf01/03` 自带大块定向裸土图案，禁止作为美化的整片草地填充；否则会每隔一个纹理周期出现重复斜角或圆斑。`Grass_Golf05` 在真实光照下还有明显斜条纹，亦排除。`Grass_Geneva01`、`Grass_CapeCod05/12` 可作当前美化的纯草地变体。夹川汇潮 T2.2.7 的实机重复三角块反馈由此修复，记录见 [纹理平铺修复](texture_tiling_fix.md)。

第二座产能的路径点与脚本必须对应。修改出生点时，也应检查 `dual-*` 路径点及固定 AI 建造场。成品回读会检查这些路径点是否存在。编辑地图内容后递增版本，再重新构建和验收。

## 脚本规则模板

`templates/rules/` 是已定稿玩法的可复用数据模板，包括公共脚本、固定 AI 科技、第二座产能和按图选择的进攻规则。模板中的 `asset` 与 `command` 使用名字；Rust 在构建时解析、检查并链接为当前地图字符串编号，不依赖模板中的数字编号碰巧一致。

容器前缀和叶子指令正文保留十六进制字段，以无损保存 SAGE 各版本的未知字节。`children` 表达层级，`command` 表达动作/条件的内部名字。阵营与队伍属性也经过原生解析和重新编号。

玩法的选择由 `RULESET` 确定。旧版 `TEAM_ATK`、`FORCE_SEA_AI` 等过程式开关已折叠进对应规则模板，不再把这些未执行的开关留在新配方中。新地图可复用合适的规则模板，或复制模板后明确修改。

`common-T0.5.1` 是通用模板，保留叠岭连原 T0.5.1 的 224 条脚本、分组、条件和启用状态。它不含电脑现金显示、电脑主动进攻、位置分队和四人落座。P8 建造场引用使用包含命名对象的同类型查找，兼容其他地图中命名为 `sea-mcv-8` 的帝国建造场。固定 AI 初始化的外交仍按源脚本执行。

通用脚本还包含公共赠送建筑规则，统一读取 `common-T0.5.1.json#/production_placement`，包括使用独立玩法模板的地图：

- **赠送避让 `gift-clear-*`**：主点被占尝试备用点，全占保留资格重试，成功后设置完成标记；检测区域覆盖玩家、固定 AI 和中立对象。运行时脚本根据各图实际赠送项目生成。
- **建筑水陆落点**：重工完整占地必须位于合格平坦陆地，船厂完整占地必须位于水域，主备点一并检查。
- **赠送建筑朝向**：赠送兵营、重工、机场和船厂按实际主备落点，分别朝向对方队伍出生航点的中心。

新蓝图 `map` 阶段完成水陆选址、避让生成和朝向设置；冻结成品构建保留来源已有的脚本和航点，两条路径均回读校验对应约束。已有成品使用 `repair-production --map <id> --bump <源ZIP>` 增量应用这三项，保留原触发条件、阵营与归属。三项是公共基础能力，不受地图专属进攻模块开关影响。公共脚本数量以“224 条基础脚本 + 按图生成的占用脚本”描述；配套构建规则不额外计为游戏脚本。增量发布后须核对并采用完整新来源，再运行当前版构建补齐坐标和 WorldBuilder 资料。详见 [公共赠送建筑规则](production_placement_fix.md) 与 [成品编辑后的衔接](coordinate_pipeline.md#成品编辑后的衔接)。

模板的 `spawn_waypoints` 声明 31 个超武、电厂航点的名称、所属出生位（1–8）和占地半径（格）。`script_spawns` 根据每张图的定稿出生点，在 14–80 格内寻找平坦、可通行、可建造的陆地，并避开资源、建筑、装饰、基地及 `dual-*` 产能点。它只追加航点，不修改地形、矿位或原有对象；找不到安全落点会使构建失败。成品回读再次检查占地与脚本航点、控制目标引用。坐标报告写入 `assets/<地图>/<生成发布名+版本>/script_waypoints.json`。采用模板的配方需提供 `MAP_STR_INFO.GameStart` 文本。

远海出生点可在配方 `SCRIPT_SPAWN_RADIUS_BY_SEAT` 中单独声明搜索上限（键为出生位编号，值为格数），仍按距离优先选择安全陆地。千流叩海 P6、P8 在远海，分别设为 360、220 格；建筑实际落在东侧陆地，所属玩家保持源脚本设定。其他出生位与另外两张图仍使用 80 格上限，占地和间距验收相同。

## 兼容性边界

2026-10-23 发布封装修复：字符串表在链接新名字后必须按 ID 严格倒序写出，不能直接沿用插入顺序。`MapFile::encode` 已统一规范化；验收与发布会检查磁盘实际顺序。地编地图的 `AssetList` 和 `map.xml` 是配套资源数据，重新封装必须同时保留，XML 的资产 ID 也不随文件夹版本号盲目替换。新的 `repack <源ZIP> --map <id> --bump [--install]` 入口用于保留全部地图区块并发布新版本；支持地编 ZIP 的 Unicode Path 文件名字段。当时普通生成图仍删除模板清单后依赖按需加载；该临时做法已在 2026-10-27 的实机反馈后废弃。当前 `resources.rs` 重新生成清单、图集、完整对象/脚本 XML，打包强制检查资源配套。

回归基线由迁移前的四张地图生成，记录每个区块的长度/CRC32、明文及压缩文件的校验值。测试会重新计算完整地图，而不是直接复制旧 `.map`。预览与 TGA 由原生渲染器生成，图像插值和文字排版可能与 Pillow 不同，轴向保持一致。

字符串表修复后，旧容器整体 CRC 不再用作通过条件；各区块的长度和 CRC 仍逐项与原基线比较，并额外验证严格字符串表顺序、容器规范编码和确定性压缩。成品重新封装测试使用已验证的地编包，检查所有区块保留、完整安装和提交前失败的版本回滚。可选安装发生在本地构建或发布提交后；此时安装失败保留已提交版号、同版成品和根蓝图镜像。

原 Python 工具的 CLI 入口已移除；常用构建、版本、打包、解压、地图检查和脚本导出命令统一为 `ra3maps` 子命令。`build.cmd` 和 `build.ps1` 仍可使用，现调用 Cargo/Rust。

## 新增地图

复制一份配方目录时，先移除原图的 `COORDINATE_PIPELINE` 来源配置，避免继续引用别图的冻结成品；删除原 `RESOURCE_ID_SEED` 以派生新地图的资源命名空间。替换分层蓝图，修改 `config.json`，并在配方指定的 `layout.json` 中编写出生点、斜坡、资源和对象。依[公共分级布矿规则](resource_distribution.md)定稿 48 矿与四条主次路线，配置 `RESOURCE_DISTRIBUTION`，再选择匹配固定 AI 水陆位置及进攻规则的 `RULESET`。构建不会再次自动搜索或移动布局点；不合格的建造盘、出生平台或斜坡会使验收失败。新图定稿并核对完整原生包、同版 `source/layout.json` 和空间结果后，可运行 `adopt-coordinate-source` 启用冻结成品模式。

`version.json` 为每张图独立维护。只有改变地图内容才递增版本；保持 `.map` 字节一致的纯工具链重构不递增版本。
