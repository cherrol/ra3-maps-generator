# 山地坡口：AXAI、NKL、SMAI 参考与改进

2026-10-28，按用户要求重点参考山地、峡谷和多层台地，读取本机三个系列的 16 张实际地图。提取原生高度、通行位图、基础材质和混合描述，并在副本上导出 WorldBuilder 实际渲染。

## 斜坡数量与通行布局

**斜坡数量不限制，不设上限或固定配额。** 数量和位置按玩家通往交战区与资源的实际需要确定；历史地图的坡数只是当版记录，不作为新图或后续修改的数量目标。

从各出生点规划通往主、次交战区及矿、油井、医院等全部中立资源的路线。应方便进军、扩张和资源接入；不能为减少坡数而留下断路、明显绕远或不必要的狭窄瓶颈。需要时按本轮制作范围增设或移动坡口，结合实际地形比较路线并记录布置依据，不能仅凭“最终可达”认定通行方便。

增设坡口仍须满足全宽坡形、双向端口、完整资源与建筑占地避让、连续导航及两层连接要求；开局基地与两矿继续同面。按[交战区与资源通行便利验收](map_acceptance.md#交战区与资源通行便利如何验)提交同版路线证据。规范更新本身不自动改变冻结成品，已有地图的整改随明确制作任务执行。

交战通行段及伸入地形分别执行[净宽与整理规则](terrain_preview.md#交战路线与伸入地形整理)：交战路线不足公共净宽时拓宽补足，细长伸入部分不足其门槛时就近归并；两类重叠时仍保证交战通路连续。上述通路门槛不降低既有坡面完整宽度要求；赠送主备完整占地同时避开所有伸入区域。

## 通用流水默认

配方 `RAMP_PROFILE` 缺省为 `mountain`，与显式设置相同；`legacy` 用于复现历史蓝图与回归基线，其他值在构建递增版本前拒绝。新蓝图读取布局时默认应用山地坡形及材质标记，生成表面时跳过旧 8×8 土路/碎石块刷法，使用当前的台地材质衔接。普通构建、`polish-ramps` 和纹理整理共用相同实现，不再另刷孤立短土斑。

烘焙蓝图保留既有高度，冻结坐标流水继续逐字节沿用已采用的原生成品，不因工具缺省变化自动重挖。已有成品的升级流程为：从该图最新完整 ZIP 执行 `polish-ramps --map <id> --bump`，回读核对受保护高度、主备赠送建筑占地及空间基准；通过后再采用新成品，导出坐标及 WorldBuilder 文件并打包安装。只整理材质使用 `polish-ramp-surfaces`。三种操作都保留各图自身层高、出生、资源及脚本规则。

候选坡口若侵入医院、矿盘等保守预留范围，会被排除；搜索附近其他安全候选仍不合格时，保留原坡形并更新材质。不会挪开对象或放宽空间基准来强行重做。旧版验证显式使用 `RAMP_PROFILE: legacy`，另有通用默认测试检查新坡面为连续草地、烘焙高度不被重挖。

## 当前成品的问题

当前坡度量级与参考样本接近，视觉差距集中在坡口和材质：

- 宽灰白土面、碎石边缘形成醒目的矩形，与上下台地脱节。
- 将纵向坡面与原有硬层界直接按侧向权重混合，会在坡肩留下折脊和尖角。
- 旧贴图被移除后，邻格仍可能保留朝向旧材质的混合数据，形成残留细框。
- 旧优化器使用早期蓝图恢复背景，不能完整反映后续手工调整的成品地形；遇到前序已存在的坏坡形，还可能阻止后续独立坡道的优化。

## 本次实现

`polish-ramps` 使用 `mountain` 坡形，材质以 `surface_style: mountain` 单独记录。既有地图通过各自定稿 ZIP 局部编辑；支持该标记的新蓝图也使用相同挖坡函数。地图的层高和位置仍来自自己的配方、布局及成品。

坡面中央保持稳定坡度，两端各约 15% 长度平缓接入台地；坡肩向外逐渐缩短切坡长度，以连续侧面接回岩壁。保留声明的长度和完整通行宽度，不用延长整段坡道来压低坡度数值。

材质从实际低、高台地周围采样，陡侧面保留岩石。T2.3.6 曾增加两端淡出的短土痕；用户实机反馈其像孤立补丁，后续 T2.3.7 已取消，坡面直接延续上下台地材质。清理旧矩形铺面及其邻格的二路、三路和崖面混合，再局部重建材质边界；保留图集及资源身份。后续 `polish-textures` 会识别此标记，继续使用山地坡口材质。

地形优化直接读取来源成品的高度和平坦台面。原先合格的所有坡道都参与保护；已有坏坡不会否决无关改动。保护范围包括基地、矿盘、建筑，以及从实际赠送动作解析出的主、备用建筑完整方形占地和位图更新余量；修正了此前只保护备用航点中心的遗漏。成品重新检查赠送建筑水陆、平坦度及避让。

空间检查的问题身份只排除纯材质字段 `surface_style`，坐标、宽度、长度、坡形和实际检测指标继续参与；改位置或恶化指标仍拒绝通过。审计缓存版本同步递增。
