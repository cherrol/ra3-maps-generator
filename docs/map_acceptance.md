# 公共地图交付验收

交战路线宽度与伸入地形、赠送建筑避开伸入区域、赠送生产建筑靠近基地、布矿、坡口、交战区与资源通行便利、整圈岸线、热点双方实际路程、建筑朝向（含矿脉）均为必检项，按本文件确定证据与交付结论。规则含义、参数和实现归属仍查[公共约束总表](map_rules.md)及相应专题规范，不在 skills 中另设数值。现有命令的自动通过不等于完整交付验收通过。

## 适用范围与结论

- **新可玩图**：各项逐一验收；地图没有水域或相应岸线时，须依据实际原生地形记录不适用原因。
- **已有图修改**：各项均列入记录，重查本轮影响项。矿位、出生点、赠送落点／归属、建筑或矿脉朝向、地形高度、坡道、阻挡或导航变化时，联动复查受影响的建筑占地、赠送生产建筑与所属基地的接入和距离、分级布矿、坡口、交战区与资源通行便利、岸线和热点路线。不能只按编辑命令名称判断影响。
- **冻结原样复现／无关修改**：允许按现行兼容规则保留原成品；未迁移布矿计划或未完成独立核查的项标为“继承未验”，不能写成符合现行完整标准。本轮新增或恶化问题仍拒绝通过。
- **纯地形预览**：交战路线宽度与伸入地形按设计数组及用途作预检；尚未规划交战路线时记录伸入区域、预留宽度及路线宽度留待可玩规划核对。赠送建筑落点、布矿、坡口玩法占地、交战区与资源通行便利、热点路程和建筑朝向不适用；岸线核对小水域单层包裹及设计覆盖，实际导航与建造回读留待可玩制作验收。

每项只能记录为“通过”“失败”“待核验”“不适用”或“继承未验”。不适用须有依据；继承项须绑定原来源及未变化证据。任何适用项失败或待核验，不得宣称完整验收通过，不得把未通过方案作为本轮定稿发布；冻结兼容复现必须单独说明其范围，不冒充新标准验收。修复后重新核对受影响项，不能通过刷新基准消除失败。

## 交战路线宽度与伸入地形如何验

1. 按[整理规则](terrain_preview.md#交战路线与伸入地形整理)及[赠送排除规则](production_placement_fix.md#赠送建筑避开伸入地形)列全本轮交战路线、实际接入点和伸入区域，记录 ID、用途、坐标、移动域及范围。公共参数读取 `coordinate-pipeline.json#/terrain_shape`，当前交战路线最低净宽 10 格、细长伸入地形最低净宽 5 格、赠送排除开启。单位为 Frame 地形格的宽度，不是面积或半径。
2. 从实际设计数组或本版原生高度／导航／实体占地，沿有效通行主体、窄颈及受阻断面逐段核对连续净宽；保留测量断面、最窄位置与测量方法。交战段不足 10 格须适当拓宽补足并保持两端可接入，不能靠中心可达、路线平均宽度或最宽处通过。斜坡等已有更大要求继续独立检查。
3. 细长伸入部分不足 5 格须就近并入实际相邻的层、陆地或水域，记录目标与局部修改范围并回读前后数组。属于交战路线的部分仍须满足 10 格并保持路线连续；不能以归并消除或切断交战通路。达到 5 格可按其他规则核对后保留，不因其已经达标就允许放置赠送建筑。
4. 从实际赠送脚本逐项列出建筑类型、归属、主备／条件分支、绑定航点、原生位置与合法朝向；核对完整建筑占地、出入口及接驳预留与全部伸入区域无重叠。只检查中心点、主点或部分阵营均不完整。拓宽后仍为伸入区域的继续排除，不得仅改名绕过。已有水陆、避让和朝向报告可复用其实际覆盖项，但不代替本项相交检查。
5. 拓宽或归并后，同步层级、水陆掩码、参考／蓝图与图片，保留原始资料及修改前快照，证明记录范围外地形保持；联动复验水陆面积、出生组同面、资源与赠送占地、坡形坡口、通行便利、保留水体的单层包裹及全周岸线、热点双方路程。仅填写策略、改图片或刷新基准不算完成。
6. 纯预览提交设计空间预检，可玩候选另回读实际原生数据；尚无交战布局时不得虚填路线证据。已证实宽度不足未处理、处理后仍不合格或赠送建筑与伸入区域重叠，记“失败”；缺少范围、测量或完整赠送清单，记“待核验”。当前尚无上述三项的完整公共自动门禁，独立记录须绑定候选身份、Frame 与参数，历史缺证据不补写通过。

## 赠送生产建筑靠近基地如何验

1. 按[所属基地选址原则](production_placement_fix.md#赠送生产建筑靠近所属基地)，从本版实际脚本列全生产建筑类型、动作／分支、受益席位、主备航点与原生落点，绑定对应实际出生点／基地及 Frame。没有此类赠送时列明依据后记不适用；归属或分支无法解析时记待核验。
2. 逐点记录到所属基地的直线距离及单位，并核对实际接入。陆上基地与陆地产能点之间提供基地到建筑出入口的可走路径及长度；陆上基地的船厂分别记录到相应岸边接入的陆路、船厂水上位置与生产出口的水路连通。水上基地及跨域情况记录所需移动能力和实际连接，不拼接不同移动域冒充单条陆路，也不将未验证的运输记为可走路径。航点中心距离只作位置对照，不替代旋转占地、出入口及路径核对。
3. 对明显偏远的主点、备用点及分支，比较更近的基地周边／近岸候选，记录实际水陆、占地、阻挡、坡口、伸入区域、主备预留和接入限制，以及选择或排除理由；可复用同版既有报告覆盖的几何与通路证据。不要求压到全局数学最短，也不以搜索半径、地图尺寸比例或未定义的统一距离阈值代替判断。
4. 已有更近且满足原约束、接入便利的候选，却无合理理由保留明显偏远落点，记失败；附近确无合格位置的，须有受限范围与候选比较，说明较远位置的必要性和实际接入后再作结论。缺少归属、路径或必要的候选比较记待核验，不能只写“已尽量靠近”。调整后复验受影响的完整占地、主备避让、水陆、朝向、资源与通路；已有冻结来源按前述兼容范围记录，不自动重布。

当前 `gift-clearance.json`、`production-spawns.json`、`production-facing.json` 及 `unit-routes.json` 均不能单独证明本项通过；本项尚无完整公共自动门禁，须提交上述独立证据。

## 交战区与资源通行便利如何验

1. 按[斜坡数量与通行布局](mountain_ramps.md#斜坡数量与通行布局)核对本图需求。斜坡数量不设上限或固定配额；只记录实际坡数，不以达到某个数量、沿用旧版坡数或少建坡口作为通过条件。
2. 列全各出生点、主／次交战区及其实际入口，以及矿、油井、医院和其他中立资源的原生目标清单，覆盖家区、外扩、热点与绕行路线。逐项记录起点、目标接入点和移动域，不以只检查近矿或热点代替其他资源及交战区。
3. 从本版原生高度、导航、实体占地和坡口计算实际可走路径，记录长度与经过的坡口，核对全宽通行及两端连续接入。可复用同版 `spatial/routes.json` 已覆盖的资源路线；交战区及其未覆盖目标须补独立证据。跨域路线记录所需移动能力和实际连接，`requires_transport` 或单条两栖路线不能证明普通陆军通行方便。
4. 检查进军与资源接入是否因坡口不足或位置不当而明显绕远、反复折返或挤经不必要的狭窄瓶颈。发现问题时，在本轮范围内比较增设／移动坡口等方案，记录实际路线变化及判断依据。只证明最终可达不够；本项不私设统一绕行比率或坡数阈值，确需保留的战术隘口须说明其设计用途及对相关路线的影响。
5. 已证实的断路或不便问题未解决，记“失败”；目标、路径或便利性判断证据缺失，记“待核验”。增设／移动后联动复查坡形、坡口完整占地、出生组、资源分级、岸线和热点双方路程。数量不限不放宽坡宽、坡度、端口或避让要求，也不能用开坡代替开局两矿同面。

当前公共自动检查仅覆盖其报告列出的坡形、占地及静态资源可达性，尚无交战区与资源通行便利的完整自动门禁。本项须独立验收并留同版证据；历史版本没有这项记录时，不补写为通过。

## 整圈岸线如何验

1. 从本版原生高度和水陆信息提取岸线，按实际连通关系列全水体、岛屿及其外边界／内边界；逐处说明是否适用连续跨层通行规则。跨出可玩框的开放边界单列，不把地图外框伪装为游戏内岸线。
2. 按[小水域单层包裹规则](terrain_preview.md#小水域的单层包裹)列出适用小水域及尺度依据。对跨层水域，以修改前分层累计各层全周共享水陆边长度，记录统计口径、归属层和并列处理理由；回读修改后分层，确认岸线陆地侧只接触该层、与该层主体连通，其他层界已绕开水域。检查内岸、尖角与窄颈，保留修改范围和前后证据；纯预览从实际分层数组核对，可玩图还须与本版原生高度及过渡设计对应。归属非最多接触层且无明确例外、仍接触多层或仅改图片，均记失败；缺少原统计或全周证据记待核验。
3. 为适用边界建立连续分段编号，记录总边界长度、已核验长度和遗漏区间。全部适用边界均须覆盖，不得跳过尖角、窄颈、背面、内湖或阻挡段。无遗漏只说明覆盖完整，还须逐段满足通行条件。
4. 按各段真实法向或实际跨岸路线采样过渡高度、宽度、坡度和两侧接入，叠加原生阻挡、导航和实体占地；按同一移动能力检查水到陆、陆到水均可通过。普通陆军或舰船不能跨域，不用它们的域限制证明岸线合格；静态模型须明确对应能力与限制。
5. 记录归层不完整、不连续、过陡、过窄、阻挡或单向失败的坐标与长度。本轮涉及的失败段修复后重验，并联动受影响的建筑占地、布矿、坡口和热点路线；少数坡口或中心可达、二维色块连片、某条两栖路径可达，均不能替代整圈验收。

现有公共流水没有完成上述单层包裹及全周自动门禁。当前须独立测量并保存结果；没有接触量、归层或逐段证据时，对应项状态为“待核验”，不得手填“通过”补齐表格。检查使用原生数据和静态模型，不要求启动游戏或 GUI。

## 热点路程如何验

1. 读取本图主线的 `side_a_seat`／`side_b_seat` 和第 5 矿原生 ID；对同一目标分别计算配对双方的路线，核对起终点实际接入，保留路径或可复算的输入、算法和接入点。
2. 双方使用相同移动域、通行余量、邻接方式、阻挡、逐格高度差和距离单位。路线必须实际可走，不能使用直线距离、声明主线长度或路径采样进度冒充到矿距离；不能用一方两栖距离与另一方陆路距离比较。
3. 普通同域路线可引用本版 `spatial/routes.json` 的 `path_steps`、`world_distance`、`start_access`、`target_access`，并绑定对应 `spatial/report.json` 的 native CRC、Frame、策略和路线模型。这是静态最短路估算，不代表游戏运行时寻路。`straight_distance_world` 只作对照。
4. `requires_transport`、`unreachable`、缺失长度或未验证接入均不能当作零距离或通过。确需两栖路线时，另提供同一能力的双向跨岸模型与实际路径证据；需要运输的路线不能凭空估算为可走。
5. 每座热点矿同时报告双方长度、绝对差和相对差，说明是否形成双方可争夺的热点及必要的调整。相对差统一用 `abs(dA-dB) / max(dA,dB)`，两侧长度均须有效且大于零。当前没有公共路程差上限，不得私设一个比率后宣称公共自动均衡通过；本图采用的设计判据和判断依据须留档。

分级报告只检查热点所在阶段和主线位置，静态通路报告只证明其所覆盖的可达性；二者都不能单独代替上述双方路程比较。

## 建筑朝向如何验

1. 按[四向规范及矿脉验收范围](production_placement_fix.md#所有建筑的四向约束)列全 `ObjectsList` 中的建筑和全部 `OreNode`，并递归核对脚本中创建、设置或改变建筑及矿脉朝向的动作。逐个主点、备用点、条件和阵营分支留证；不把航点角度当作创建动作的角度，不因油井或矿脉在资源分类中就跳过。分别记录建筑、矿脉及各类动作数量，与原生成品核对覆盖完整。
2. 从候选原生地图回读对象 angle 与脚本 ANGLE，按弧度和世界坐标解释，再模整周归一化。按规范的浮点误差容限核对四个允许方向，列出对象／动作 ID、建筑或矿脉类型、位置或航点、原始弧度、归一化度数、与最近允许方向的偏差及判定。矿脉另核对内部角度、原生角度和翻 Y 后实际矿口方向一致。未显式指定朝向、动态计算朝向或其他不能证明运行结果限于四向的动作记待核验；已证明产生非法方向记失败，不先吸附角度再判原成品通过。
3. 赠送建筑另核对其是否选择朝向对方队伍中心的最近合法方向。`production-facing.json` 只证明其列出的赠送动作；公共 `ore_facing` 输出 `ore-facing.json`，检查全部矿脉对象、显式矿脉创建及可解析的命名矿脉转向，覆盖真假和嵌套分支；缺少常量绝对角度的动作记待核验并拒绝通过。未解析的间接脚本目标仍须独立核对。两者均不替代其他建筑的完整清单和占地证据，不得以局部模块通过推断本项完整通过。
4. 修改建筑或矿脉角度后，同步关联表示并复查旋转地基、出入口、完整矿场规划矩形、矿口接驳、坡口、赠送主备预留及受影响通路。清单遗漏矿脉、角度不合法或复查失败，均不能把“建筑朝向”记为通过；已知非法矿脉角度不能记为继承未验。本轮规范更新本身不自动修改既有地图。

## 执行、记录与交付

先执行当前公共入口：

```sh
cargo run --release --locked -- accept --map <id>
```

冻结坐标流水的分级布矿、坡口、坡形与路线结果见 `assets/<id>/<发布名>/spatial/report.json` 和 `spatial/routes.json`；普通蓝图构建读取同版 `resource-distribution.json`、`spawn-placement.json` 及实际验收输出。缺少某类报告时须执行相应公共检查或补独立证据，不把文件不存在解释为通过。

随后完成全部必检项记录，建议保存为 `assets/<id>/<发布名>/acceptance.md`，连同所引用的原始数据与测量结果归档到 `maps/<id>/histories/<版本>/`。每份记录必须包含：

- 地图、版本、候选原生地图哈希或 CRC、Frame、公共规则／策略、本图计划及布局身份、检查方法与日期；仅绑定旧源 CRC 不足以证明候选合格。
- 各项的适用范围、状态、测量值、证据路径、失败位置，以及冻结来源继承或本轮明确例外。面积均衡等其他既有要求继续按公共总表验收。
- 交战路线及细长伸入区域的完整范围、逐段净宽、拓宽／归并前后证据，以及赠送建筑全部主备／分支完整占地与伸入区域的相交结果；分别记录三项结论，不能以其中一项通过代替其他项。
- 赠送生产建筑各主备／分支的受益席位与所属基地绑定、距离及接入证据；偏远落点附更近候选的比较和选择理由，按上述专项记录结论。
- 小水域调整前各层接触长度、归属层、前后分层及全周单层包裹结果，整圈岸线的逐段覆盖与双向结果，热点每个目标的双方路程比较；不可用一张总览图或一行“人工通过”代替。
- 各出生点通往交战区与完整资源目标清单的实际路径、长度、经过坡口及便利性判断，绕行／瓶颈问题和增设／移动方案的处理结果；实际坡数仅作记录。
- 全部建筑与矿脉的逐对象／逐动作角度清单、各类覆盖数量和旋转后占地结果；预置对象及脚本创建／转向均须覆盖，不得省略 `OreNode`。
- 独立验收结论与命令自动结果分别列出。先核对全部必检项及本轮差异，再按 ra3-pipeline 定稿、发布、安装或采用新来源。

若候选、布局、路线计划、通行策略或相关规则变化，旧证据不得直接复用。只有证明该项所依赖的几何、阻挡、实体及策略未变化，才能沿用测量并重新绑定本版候选身份；其他情况重新验收。

本文件规定 skills 的交付验收要求；目前 CLI `accept` 仍只执行已有自动检查，不会自动读取独立记录，也不会自动拒绝缺少路线净宽、伸入地形整理、赠送伸入区域排除、赠送生产建筑靠近基地、通行便利、岸线、路程或未覆盖建筑角度证据的交付。执行者必须补齐适用项，不能把文档要求描述为已经实现的程序门禁。
