# 公共地图交付验收

本文件统一验收证据、判定与交付记录。规则含义、参数和实现归属见[公共约束总表](map_rules.md)及专题规范；下表索引各项适用范围，详细章节列证据与判定，不在技能或验收中另设数值标准。

## 适用范围与结论

- **新可玩图**：逐项验收；没有水域或相应岸线时，依据原生地形记录不适用原因。
- **已有图修改**：各项列入记录，重查本轮影响项。矿位、出生点、中立建筑、交战区、赠送落点／归属、朝向、高度、坡道、阻挡或导航变化时，联动占地、产能接入与距离、布矿、坡口、通行、岸线和热点路线；不能只按命令名称判断影响。对象仅在任务范围内必要联动。
- **完整来源／原样重建／重新封装**：同样执行当前两矿及严格零问题门禁。已有问题、缺少分级计划、旧三矿或历史参考均不放行；完整来源用于读取和保护无关内容，不构成豁免。
- **纯地形预览**：按设计数组预检路线宽度、伸入区域及水域单层包裹；未规划交战路线时保留宽度预留并记录待可玩规划核对。赠送、布矿、坡口玩法占地、资源通行、热点及朝向不适用，原生导航／建造和实际岸线过渡留待可玩验收。

每项只记“通过”“失败”“待核验”或有依据的“不适用”。失败或待核验均阻止定稿、发布、安装和采用来源；没有“继承未验”放行状态，刷新基准不能消除失败。历史缺证据不得补填通过，修复后重查受影响项。

**统一的证据边界**：`accept` 只执行已实现的自动检查；分发、安装、增量发布和采用来源另外读取下述结构化独立验收记录。自动通过仅覆盖报告实际检查的对象、动作和规则；发布入口核对独立记录的完整性、状态与候选身份，不自动作出设计判断。不能从自动几何零冲突推定斜坡优先级、路线或选址设计已经通过。检查使用原生数据和静态模型，不要求启动游戏或 GUI。

## 地形交接如何验

1. 按[地形交接规范](terrain_transitions.md)建立本图坡道、层界、岸线及其交汇处的清单，列分段 ID、范围、类型、两侧层级／水体、预期连接或阻断、适用移动能力和本轮修改。覆盖坡肩、端口、崖脚、岸线转角、窄颈及三材／三层交点，不能只选几处好看的坡口。纯预览核对实际设计数组及过渡空间预留，不虚填尚未生成的剖面、纹理或导航结论。
2. 可玩候选回读原生高度与水面，保存坡面纵向和全宽平行剖面、坡肩横断面、层界法向剖面及陆台到水下的跨岸剖面，标注采样格坐标、间距、实际高差、坡度和端部接入。联合检查坡口、层界与岸线交汇处的折脊、端缝、尖峰、陡坎和单格裂口，确认可走坡面完整、不可走层界未意外开放。参考样本数值不作为本图的合格阈值。
3. 叠加原生导航、阻挡、全部资源和建筑／赠送主备及分支的完整占地、出口及接驳，按声明的移动能力核对预期双向连接或阻断，保存最窄断面、实际路径及失败坐标。岸线继续按[整圈检查](#整圈岸线如何验)证明覆盖；单个禁行位为零、中心可达或局部剖面平滑均不足以通过。
4. 分别检查主材、普通混合、第二混合平面、存在的悬崖 UV 与子贴片相位，核对岩壁是否横穿坡口、沙带是否爬上陡壁、多材交点是否残留细框或硬块，以及道路／地表是否连续接回台地。保存同版原生数据和局部外观证据，并注明图像由原生字段示意、真实贴图离线合成还是已有渲染得到；示意图不冒充真实渲染，旧渲染不冒充本版外观。生产流程不要求启动游戏或 GUI，缺少可支持外观判断的证据时如实记待核验。
5. 高度、导航和材质分别作结论，注明各工具实际改变的内容；`polish-textures`、材质直方图、封装修复或 CLI 成功均不证明几何和通行整改。已知折脊、硬岸坡、材质断框、错误封岸或交汇阻挡未处理记失败；清单、剖面、混合、外观或相关通行证据缺失记待核验。修复后复查受影响的出生组、完整矿场、赠送、路线及热点路程，按同一候选身份归档并证明范围外保护。

本章补充现有专业判据，不新增结构化验收 ID：`route_width_intrusions` 承接全图交接清单及层界／交汇的联合结论，`ramp_clearance`、`shore_perimeter`、`resource_access` 分别引用其中坡道、岸线和接入证据；无坡、无水不使层界交接自动不适用。共享证据用同一分段 ID 和候选身份，不重复造表。当前程序不解析上述几何、材质或视觉判断，仍由专业审阅完成。2026-10-30 已更新独立验收规则修订号，旧记录须补查这些判据再重新绑定；不能只替换修订号延续旧通过。

## 对位进攻方向与沿线布置如何验

1. **端点、方向与直接主路**：从实际出生位置、玩家／固定AI身份和移动域确定对位，逐对记录两基地原生身份、端点及连线方向，以该连线作为大致主攻方向。先定连续、直接的主路和沿线坡位，再安排侧翼与矿位；主路不得出现不必要的绕远。逐处记录真实层界、水域等造成的合理转折及更直接候选比较。配对、控制点和坡数由本图确定；不新增角度、距离比例或绕行阈值，连线不能替代实际路径。
2. **沿线坡位与层界轴向**：沿拟定路线的真实低高层交界选择坡位，记录对应线路、连接层、低高端口、坡宽及两端接入。坡轴按层界和真实标高确定，不要求平行于基地连线；完整坡口与矿坡冲突证据统一见[斜坡优先级验收](#斜坡优先级如何验)。
3. **两矿与外围散布**：按[分级布矿](resource_distribution.md)登记全部原生矿及阶段、总数和家区配额。逐矿记录 ID、阶段、坐标、全部基地家区关系、路线及实际接入，核对外围矿退出所有基地家区、沿主攻／侧翼路线分散，不形成基地第三矿或沿线集中堆放。路线位置读取生效参数，不新增散布间距；移矿后的出生组与完整占地复验复用下一节证据。
4. 路线、坡位、矿位、赠送点或阻挡改变后，按[净宽与完整赠送叠加检查](#交战路线宽度与伸入地形如何验)复验，资源接入另按[通行便利](#交战区与资源通行便利如何验)补齐。
5. **判定**：主路不必要绕远、坡位脱离路线、外围矿回入家区、散布不符或叠加后净宽不足且未处理，记失败；缺少实际端点、方向、线路、转折依据、全部矿坡落点或独立布局判断，记待核验。坡矿优先级另作结论，不能与路线可达合并为一次通过。

## 斜坡优先级如何验

1. **范围与基准**：按[斜坡优先级与冲突处理](ramp_clearance.md#斜坡优先级与冲突处理)列全主攻、侧翼及资源接入坡道和开局、外围矿，绑定本版候选及原生 ID。保存已确认的路线、真实层界和合格坡道设计；逐坡记录坡体范围、坡心／轴向、宽长、两端落地段与完整上下引道。已有图同时保存修改前数据，新图保存安排矿位之前的坡道设计，不能从迁就矿位后的坡形反建基准。
2. **完整几何**：回读全宽坡面、两端落地及轴向通行区，采样坡度、端缝、阻挡和双向连接；叠加全部矿盘、按最终合法矿口角度旋转的完整矿场及接驳。记录冲突坡 ID、矿 ID、交叠位置、生效策略和处理方案；无冲突也须保留完整覆盖依据。油井、中立建筑、赠送主备及分支另按同一[坡口预留](ramp_clearance.md)检查，保存坡形采样、完整占地检查和 `ramp_clearance` 严格零发现报告。
3. **冲突处理与差异**：逐项保存移矿前后位置、朝向及实际位移，同步布局、分类清单、原生对象和相关脚本表示。将最终坡体、宽长、轴向、端口和引道与基准逐项比较，核对未为保矿削坡、缩坡、移坡或缩减预留；因层界、坏坡修复或通行改善而改坡的，另附地形／路线依据。局部工具拒绝碰矿候选、改试其他坡位或返回仅材质更新，均不构成冲突已解决的证据。
4. **联动复验**：移矿后复验分级与配额、开局两矿近矿范围和同面连续空间、完整矿盘／旋转矿场／接驳、合法朝向、坡口和实际通路；受影响的路线净宽、赠送预留、岸线与热点双方路程按各章复查。可引用同版共享测量，不重复计算；不能靠删矿或放宽资源标准换取坡口零冲突。
5. **独立判定**：为保矿削改、缩窄、缩短或移动既定合理坡道、改走远坡、缩小完整预留，或仍有已知冲突，记失败。缺少基准、全量清单、差异、移矿结果或必要复验，记待核验。完整来源、矿位未动或自动 `passed` 均不能替代本项；纯地形预览按适用范围记不适用。

## 交战路线宽度与伸入地形如何验

1. 按[整理规则](terrain_preview.md#交战路线与伸入地形整理)及[赠送排除规则](production_placement_fix.md#赠送建筑避开伸入地形)列全本轮交战路线、实际接入点和伸入区域，记录 ID、用途、坐标、移动域及范围。公共参数读取 `coordinate-pipeline.json#/terrain_shape`，当前交战路线最低净宽 10 格、细长伸入地形最低净宽 5 格、赠送排除开启。单位为 Frame 地形格的宽度，不是面积或半径。
2. 从实际设计数组或本版原生高度／导航／实体占地，沿有效通行主体、窄颈及受阻断面逐段核对连续净宽。新增／变更线路先完整叠加全部潜在赠送主备／条件分支地基、出口及接驳预留，逐项列出覆盖的动作／航点和实际角度；无赠送场景或单组已抽取主点通过均不能作为最终净宽结论。保留测量断面、最窄位置与测量方法。交战段不足 10 格须适当拓宽补足并保持两端可接入，不能靠中心可达、路线平均宽度或最宽处通过。斜坡等已有更大要求继续独立检查。
3. 细长伸入部分不足 5 格须就近并入实际相邻的层、陆地或水域，记录目标与局部修改范围并回读前后数组。属于交战路线的部分仍须满足 10 格并保持路线连续；不能以归并消除或切断交战通路。达到 5 格可按其他规则核对后保留，不因其已经达标就允许放置赠送建筑。
4. 从实际赠送脚本逐项列出建筑类型、归属、主备／条件分支、绑定航点、原生位置与合法朝向；核对完整建筑占地、出入口及接驳预留与全部伸入区域无重叠。只检查中心点、主点或部分阵营均不完整。拓宽后仍为伸入区域的继续排除，不得仅改名绕过。已有水陆、避让和朝向报告可复用其实际覆盖项，但不代替本项相交检查。
5. 拓宽或归并后，同步层级、水陆掩码、参考／蓝图与图片，保留原始资料及修改前快照，证明记录范围外地形保持；联动复验水陆面积、出生组同面、资源与赠送占地、坡形坡口、通行便利、保留水体的单层包裹及全周岸线、热点双方路程。仅填写策略、改图片或刷新基准不算完成。
6. 纯预览提交设计空间预检，可玩候选另回读实际原生数据；尚无交战布局时不得虚填路线证据。已证实宽度不足未处理、处理后仍不合格或赠送建筑与伸入区域重叠，记“失败”；缺少范围、测量或完整赠送清单，记“待核验”。

## 赠送生产建筑靠近基地如何验

1. 按[所属基地选址原则](production_placement_fix.md#赠送生产建筑靠近所属基地)，从本版实际脚本列全生产建筑类型、动作／分支、受益席位、主备航点与原生落点，绑定对应实际出生点／基地及 Frame。没有此类赠送时列明依据后记不适用；归属或分支无法解析时记待核验。
2. 逐点记录到所属基地的直线距离及单位，并核对实际接入。陆上基地与陆地产能点之间提供基地到建筑出入口的可走路径及长度；陆上基地的船厂分别记录到相应岸边接入的陆路、船厂水上位置与生产出口的水路连通。水上基地及跨域情况记录所需移动能力和实际连接，不拼接不同移动域冒充单条陆路，也不将未验证的运输记为可走路径。航点中心距离只作位置对照，不替代旋转占地、出入口及路径核对。
3. 对明显偏远的主点、备用点及分支，比较更近的基地周边／近岸候选，记录实际水陆、占地、阻挡、坡口、伸入区域、主备预留和接入限制，以及选择或排除理由；可复用同版既有报告覆盖的几何与通路证据。不要求压到全局数学最短，也不以搜索半径、地图尺寸比例或未定义的统一距离阈值代替判断。
4. 已有更近且满足原约束、接入便利的候选，却无合理理由保留明显偏远落点，记失败；附近确无合格位置的，须有受限范围与候选比较，说明较远位置的必要性和实际接入后再作结论。缺少归属、路径或必要的候选比较记待核验，不能只写“已尽量靠近”。调整后复验受影响的完整占地、主备避让、水陆、朝向、资源与通路；已有完整来源同样需要当前合格证据，来源身份不构成选址豁免。

`gift-clearance.json`、`production-spawns.json`、`production-facing.json` 和 `unit-routes.json` 按其字段提供几何、脚本或静态通路证据；本节选址结论须来自基地距离、出口接入和必要的近点比较。

## 中立建筑选址如何验

1. 按[选址规则](resource_distribution.md#中立建筑的交战区选址)标出本图拟定的中间交战区及其实际入口，列全车库、医院、机场、精兵学院等适用中立建筑的原生 ID、类型、坐标与完整占地；区域须对应本图出生布局、地形和进军路线。
2. 逐座记录距最近出生点的距离、对应座位和单位，结合基地周边布局及实际接入路径核对是否离出生点过近。检查全部出生位，不只比较两队中心；本项没有公共固定格数阈值，逐图保存判断依据。
3. 对照交战区检查建筑是否分散在其附近，避免全部集中成一团，并核对双方到各落点的实际可走路径、出入口和接驳空间。位于出生点附近、偏离拟定交战区或过度集中的落点须在本轮范围内重新选择，移动后复查完整占地、坡口、朝向和通行。
4. 逐项记录分散布置、靠近交战区及远离出生点的结论。已确认不符且未处理的记“失败”；缺少区域、落点、距离、路径或判断证据的记“待核验”。完整来源和未改位置不能替代本项当前证据。


## 交战区与资源通行便利如何验

1. 主路直接性、矿坡优先与两矿微调统一按[路线章节](#对位进攻方向与沿线布置如何验)留证；本节补各出生点到主／次交战区及全部资源的接入。斜坡按[通行需求](mountain_ramps.md#斜坡数量与通行布局)增设或移动，不设数量上限或配额，实际坡数只作记录。
2. 列全交战区入口及矿、油井、医院等中立资源的原生目标ID，覆盖家区、外扩、热点与绕行线。逐项记录起点、目标接入点、移动域、原生实际路径、长度及经过坡口，核对全宽与两端连续接入；同版 `spatial/routes.json` 可提供已覆盖资源，其他目标补测。
3. 对明显绕行、折返和不必要瓶颈，保留位置、原因及增设／移动坡口前后路线比较和布置判断；必要战术隘口须说明用途及对相关路线的影响。跨域路线列所需能力和实际连接，`requires_transport` 或单条两栖路径不能证明普通陆军方便通行。
4. 断路或不便已确认却未解决，记失败；目标、路径或便利性判断缺失，记待核验。调整后联动完整坡形／坡口、出生组、布矿、岸线和热点路线；坡数、最终可达不能代替便利性结论，也不能靠开坡替代开局两矿同面。

## 整圈岸线如何验

1. 从本版原生高度和水陆信息提取岸线，按实际连通关系列全水体、岛屿及其外边界／内边界；逐处说明是否适用连续跨层通行规则。跨出可玩框的开放边界单列，不把地图外框伪装为游戏内岸线。
2. 按[小水域单层包裹规则](terrain_preview.md#小水域的单层包裹)列出适用小水域及尺度依据。对跨层水域，以修改前分层累计各层全周共享水陆边长度，记录统计口径、归属层和并列处理理由；回读修改后分层，确认岸线陆地侧只接触该层、与该层主体连通，其他层界已绕开水域。检查内岸、尖角与窄颈，保留修改范围和前后证据；纯预览从实际分层数组核对，可玩图还须与本版原生高度及过渡设计对应。归属非最多接触层且无明确例外、仍接触多层或仅改图片，均记失败；缺少原统计或全周证据记待核验。
3. 为适用边界建立连续分段编号，记录总边界长度、已核验长度和遗漏区间。全部适用边界均须覆盖，不得跳过尖角、窄颈、背面、内湖或阻挡段。无遗漏只说明覆盖完整，还须逐段满足通行条件。
4. 按各段真实法向或实际跨岸路线采样过渡高度、宽度、坡度和两侧接入，叠加原生阻挡、导航和全部实体／潜在赠送分支占地；按同一移动能力检查水到陆、陆到水均可通过。从水线到实际归属台地主体的整条接入链均按最终叠加复核，不能只验证水线一格或沿用穿过建筑的旧地形路径；必要绕行须保存新的实际链。普通陆军或舰船不能跨域，不用它们的域限制证明岸线合格；静态模型须明确对应能力与限制。
5. 记录归层不完整、不连续、过陡、过窄、阻挡或单向失败的坐标与长度。本轮涉及的失败段修复后重验，并联动受影响的建筑占地、布矿、坡口和热点路线；少数坡口或中心可达、二维色块连片、某条两栖路径可达，均不能替代整圈验收。

没有接触量、归层或逐段证据，记待核验；不得用一张总览图或一行“人工通过”补齐全周记录。

## 热点路程如何验

1. 读取本图主线的 `side_a_seat`／`side_b_seat` 和第 5 矿原生 ID；对同一目标分别计算配对双方的路线，核对起终点实际接入，保留路径或可复算的输入、算法和接入点。
2. 双方使用相同移动域、通行余量、邻接方式、阻挡、逐格高度差和距离单位。路线必须实际可走，不能使用直线距离、声明主线长度或路径采样进度冒充到矿距离；不能用一方两栖距离与另一方陆路距离比较。
3. 普通同域路线可引用本版 `spatial/routes.json` 的 `path_steps`、`world_distance`、`start_access`、`target_access`，并绑定对应 `spatial/report.json` 的 native CRC、Frame、策略和路线模型。这是静态最短路估算，不代表游戏运行时寻路。`straight_distance_world` 只作对照。
4. `requires_transport`、`unreachable`、缺失长度或未验证接入均不能当作零距离或通过。确需两栖路线时，另提供同一能力的双向跨岸模型与实际路径证据；需要运输的路线不能凭空估算为可走。
5. 每座热点矿同时报告双方长度、绝对差和相对差，说明是否形成双方可争夺的热点及必要的调整。相对差统一用 `abs(dA-dB) / max(dA,dB)`，两侧长度均须有效且大于零。当前没有公共路程差上限，不得私设一个比率后宣称公共自动均衡通过；本图采用的设计判据和判断依据须留档。


## 建筑朝向如何验

1. 按[四向规范及矿脉验收范围](production_placement_fix.md#所有建筑的四向约束)列全 `ObjectsList` 中的建筑和全部 `OreNode`，并递归核对脚本中创建、设置或改变建筑及矿脉朝向的动作。逐个主点、备用点、条件和阵营分支留证；不把航点角度当作创建动作的角度，不因油井或矿脉在资源分类中就跳过。分别记录建筑、矿脉及各类动作数量，与原生成品核对覆盖完整。
2. 从候选原生地图回读对象 angle 与脚本 ANGLE，按弧度和世界坐标解释，再模整周归一化。按公共允许方向 `[45, 135, -45, -135]` 度及浮点误差容限核对，列出对象／动作 ID、建筑或矿脉类型、位置或航点、原始弧度、归一化度数、与最近允许方向的偏差及判定。矿脉另核对内部角度、原生角度和翻 Y 后实际矿口方向一致。未显式指定朝向、动态计算朝向或其他不能证明运行结果限于四向的动作记待核验；已证明产生非法方向记失败，不先吸附角度再判原成品通过。
3. 赠送建筑另核对其是否选择朝向对方队伍中心的最近合法方向。`production-facing.json` 只证明其列出的赠送动作；公共 `ore_facing` 输出 `ore-facing.json`，检查全部矿脉对象、显式矿脉创建及可解析的命名矿脉转向，覆盖真假和嵌套分支；缺少常量绝对角度的动作记待核验并拒绝通过。未解析的间接脚本目标仍须独立核对。其余建筑按本节完整清单与旋转占地逐项补验。
4. 修改建筑或矿脉角度后，同步关联表示并复查旋转地基、出入口、完整矿场规划矩形、矿口接驳、坡口、赠送主备预留及受影响通路。清单遗漏矿脉、角度不合法或复查失败，均不能把“建筑朝向”记为通过；已知非法矿脉角度直接记为失败，不能以来源未改为由保留通过状态。

## 执行、记录与交付

### 结构化独立验收门禁

所有交付入口读取 `delivery-acceptance.json`，默认位于同版 `assets/<id>/<发布名>/`；也可由本图 `DELIVERY_ACCEPTANCE` 指向地图目录内的审核记录。schema、规则语义版本、固定必检 ID 与身份计算统一由 `src/pipeline/acceptance.rs` 维护。旧 Markdown、历史 `acceptance.json` 或自动报告不自动转换为通过。

记录绑定本图、本版、全部实际候选文件、原生内容、Frame、完整同版布局、生效参数及分级计划。每项保留审核判断与证据文件的路径、CRC 和长度；状态使用 `passed` 或有原因和实际依据的 `not_applicable`。`pending`、失败、未知状态、漏项、证据缺失／变化、候选或规则身份不符均拒绝交付。坡矿优先、主备先后及产能选址等仍由各专业完成独立判断，程序只核对记录与实际输入的关系。

证据文件的 CRC 和长度证明归档内容未变，不证明任意图表或旧自动报告的测量结论适用于当前候选。审核者须在各项 `decision` 说明证据与本候选的关系；沿用旧材料时，按下文证明相关输入、模型及覆盖未变。门禁不解析任意证据内容的设计语义，也不把补写文件哈希当作重新验收。

候选准备与发布分开：先生成地图及同版 `source/layout.json`，再运行：

```sh
cargo run --locked -- prepare-delivery --map <id>
```

该命令保存完整候选和 `delivery-acceptance.pending.json` 到本图 `data/delivery-candidates/<发布名>/<身份>/`，不递增版本或发布。完成审核后保留各项证据，把本图 `DELIVERY_ACCEPTANCE` 指向审核记录的地图内相对路径，再重试原发布操作。增量编辑在缺少有效记录时也保留此类候选并拒绝提交版本；同一输入可重新执行，候选改变须重新审核，不覆盖旧人工判断。

### 自动检查与专业记录

先运行当前公共入口：

```sh
cargo run --release --locked -- accept --map <id>
```

完整来源的分级、坡口、坡形及资源路线读取同版 `assets/<id>/<发布名>/spatial/report.json`、`spatial/routes.json`；蓝图构建读取同版 `resource-distribution.json`、`spawn-placement.json` 及实际验收输出。按上表索引和各章证据清单完成独立核查，建议汇总为 `assets/<id>/<发布名>/acceptance.md`，原始测量归档 `maps/<id>/histories/<版本>/`。统一保留：

- **身份与结论**：地图／版本、候选原生哈希或CRC、Frame、生效规则与策略、布局／计划身份、方法／日期，各项适用范围、状态、测量值、证据路径、失败位置及明确设计选择的影响。旧源CRC不足以绑定候选；自动与独立结果分列。
- **出生布局专项**：原生航点与座位对应、所选对置方向、P5/P6两角和P7/P8中间位置标注及独立结论；完整出生组和两队水陆面积分别按[出生点规则](spawn_placement.md)验收。自动方位结果不替代角落／中间核查，面积均衡不以出生组通过推断。
- **逐项原始证据**：按矩阵所引章节保存完整对象／动作／目标／边界清单、坐标范围、前后数组、角度与完整占地、实际路径及比较判断。斜坡优先级、路线宽度、伸入归并、赠送排除分别作结论；不以其他项通过代替其中一项。矿数按分级规范分别汇总开局矿与外围矿。
- **修改保护**：完整原生前后差异，覆盖对象身份／类型／属性／归属、完整脚本树与玩法触发，以及任务内必要的矿／坡／中立／赠送落点、朝向和关联检查区变更。不得为消除冲突扩大无关修改。

候选、布局、路线、通行策略或规则改变时，先重查受影响项。沿用证据须核对原报告的原生／布局／计划／Frame输入身份，证明本项生效规则与参数、检查模型和覆盖范围仍适用，所依赖的几何、阻挡与实体未变，再绑定本版。仅地图字节不变不足以覆盖新要求；主路直接性等新增判据或原报告漏项必须补证，缺证据仍记待核验，不以旧可达／净宽结论代替。

全部必检项及本轮差异核对后，按制作流水定稿、发布、安装或采用来源。完整源、同版游戏文件封装和冻结重建的字节核对继续按[流水与版本](blueprint_versions.md)及[可复现构建](reproducible_builds.md)执行；采用新基准不替代差异检查。
