# 通用坡口避让：资源与中立建筑

规则来源与其他门禁的关系统一见[公共约束总表](map_rules.md)。坡口避让、出生组与分级布矿须共同满足，不能以一种检查通过替代其他检查。

所有地图缺省启用资源与中立建筑的坡口避让。位置由本图 `coordinates::Frame` 计算，坡道、矿、油井、医院等使用同一格坐标系；不能从预览 PNG 像素或其他地图的边框、格长推算。新图布局读取配方 `LAYOUT`（默认 `layout.json`），冻结成品读取 `COORDINATE_PIPELINE.layout` 及 CRC 绑定的完整来源包。坐标声明与制作输入见 [通用坐标流水](coordinate_pipeline.md)。

## 斜坡优先级与冲突处理

**斜坡的优先级高于矿。** 本规则适用于全部已确认的合理坡道，包括主攻、侧翼和资源接入坡道；开局矿、外围矿和冻结来源中的矿位均须退让。以本轮确认的路线、真实层界及合格坡形为依据，先保留完整坡体、坡宽、两端落地段和上下引道，再安排矿盘、旋转矿场及矿口接驳。路线选取与坡轴方向分别按[沿路布置](resource_distribution.md#对位进攻路线与沿路布矿)和[层界定向](mountain_ramps.md#沿路线选坡位与按层界定朝向)确定。

发生完整占地冲突时，调整矿位及必要的合法矿口朝向，不削改、缩窄、缩短或移动既定坡道，不缩减坡口、引道、矿盘及矿场预留。可玩制作允许按[边界保护规则](preview_terrain_lock.md)添加斜坡，新坡同样先保完整坡体与引道、再布矿；需要改动层边界或水陆边界时返回预览制作阶段。

移矿后仍须满足[出生组](spawn_placement.md)、[分级配额与沿线布局](resource_distribution.md)、完整矿场及通路约束；开局两矿可在基地周边作必要小幅联动，不能放宽同面、近矿范围或数量要求。没有同时满足这些条件的方案时，冲突仍未解决，不能删矿、削坡或放宽标准换取通过。其他资源、建筑及本轮范围外内容继续按已确认范围保护。

可玩制作中的矿坡冲突通过矿位退让和布局复验处理，添加斜坡不构成为保矿削改既有坡道的理由。最终几何零冲突、边界保护和[斜坡优先级验收](map_acceptance.md#斜坡优先级如何验)须分别通过；自动报告不替代边界保持及布局判断。

## 公共策略与占地

公共参数位于 `rules/coordinate-pipeline.json#/ramp_clearance`，由 `src/terrain/ramp_clearance.rs` 读取；本图 `config.json` 的 `RAMP_CLEARANCE` 可覆盖部分字段。当前公共默认值如下，不是某张地图固定的坡宽或配额：

```json
{
  "approach_extension": 25.0,
  "gap": 8.0,
  "refinery_back": 5.0,
  "refinery_forward": 48.0,
  "refinery_half_width": 18.0
}
```

坡面、声明端口与沿坡轴双向延伸区的完整宽度均参与检查；声明落地段计入端口，再各向外延伸 `approach_extension`。矿脉同时检查半径 20 格矿盘和按矿口朝向确定的完整矿场规划矩形，默认向后 5 格、向前 48 格、左右各 18 格；油井采用半径 6 格、中立建筑采用半径 8 格的预留占地。这三个半径由模块的 `radius()` 定义，`RAMP_CLEARANCE` 覆盖上述五个策略字段。预留边缘到通行区的净距至少为 `gap`，不能仅检查对象中心是否落在坡面上；不同高度的无关台地按端口标高过滤。

本项采用保守规划预留，不以三阵营矿场的官方几何替代矿盘与矿场规划矩形。最终场景另按[官方资源流水](official_resource_pipeline.md)检查适用的放置形状、碰撞几何和生产出口；矿场报告中的官方几何、建议偏移与限制区作为独立事实记录，不等于坡口检查已按精确矿场模型计算。

## 统一严格验收

新图、当前完整原生源、坐标编辑、原样重建与重新封装统一要求零冲突。`validate_transition` 检查最终候选，不再比较或继承来源中的旧问题。完整包和 CRC 用于证明来源、保护身份及检查实际差异，不能豁免当前坡口标准。`RAMP_CLEARANCE_REFERENCE` 已移除并明确拒绝；`reference()` 仅作只读诊断。

坡声明的几何指纹以 `1e-9` 精度的固定点整数规范化，避免布局 JSON 往返的浮点末位误差；实际碰撞距离和通行阈值不量化，原生高度与对象保持精确绑定。

报告保存当前 `raw_passed`、`passed`、全部 `findings` 和 `regressions`。通过时两项布尔值均为真、发现项为空、`inherited` 为 0，`status` 为 `strict`。缺布局、来源损坏或检查失败都不能用已有包、基准或发布记录替代。

坡口与[斜坡优先级](map_acceptance.md#斜坡优先级如何验)为独立必检项。避让报告不替代坡面全宽、端缝、阻挡和双向连接检查；变更后的证据绑定与联动复验统一按[公共交付验收](map_acceptance.md)执行。

`map`、`verify`、`dist`、安装、`adopt-coordinate-source` 以及增量编辑发布入口均执行严格门禁，策略参与缓存绑定。缓存中改变或遗漏坡道定义必须匹配已验收的原生编辑证明。采用来源与发布事务按[坐标流水](coordinate_pipeline.md)和[版本资料](blueprint_versions.md)执行。
