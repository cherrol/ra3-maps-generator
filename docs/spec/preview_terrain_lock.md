# 地图制作中的边界保护与斜坡添加

## 制作依据与优先级

**制作地图过程中不允许修改层边界、水陆边界，允许添加斜坡。** 预览设计阶段确定分层和水陆轮廓；预览定稿后的新图制作与已有图增量编辑均保持这两类边界，新增斜坡可改变必要的局部坡面高度及通行关系。

- 新图基准是选定的 `preview.png` 及同版分层、水陆掩码、设计高度和 Frame；带线稿及中心标点图表达同一边界。`source.png` 仅为真实地形参考，构建后的布局图也不替代设计基准。
- 层边界按设计分层标签／掩码和 Frame 确定，水陆边界按同版水陆掩码确定。新增斜坡跨接既定层界时可形成连续高度，但不重切层、不改分层归属，也不改变实际水陆类别；不以坡面上的中间高度等值线代替设计层边界。
- 不通过拓宽、归并、归层、改岸或铺平台改变层边界、水陆轮廓、岛屿／半岛／支汊。新增斜坡的必要局部高度及导航变化单独记录；坡外地形和本轮无关的既有坡道保持。
- 已有地图以完整冻结原生来源及其同版边界资料为基准，保留无关身份。来源与选定预览的边界冲突时先记录差异并停止相关制作，不自行覆盖任一方，不重绘预览追认越界改动。
- 只有图片时按图判读，未知边界或高度如实记录；缺少边界依据时先补齐，确需修订边界则返回预览阶段。新增斜坡设计可在可玩制作中完成，保存坡位、连接层、端口、宽长、局部高度范围及预期通行，不依赖未经核对的构建默认值。基准文件、版本／校验和及坐标换算随交接保存。

## 可玩制作允许的处理

1. 在既定层边界和水陆边界内选择路线、出生组、矿、赠送及中立建筑位置；保护有效坡体、端口及完整引道，坡矿冲突调整矿位。
2. 按主攻、侧翼及资源接入需要添加斜坡，记录局部高度和通行变化，核对两侧接入、坡肩、岸线交汇及完整占地；新增坡同样执行坡口、净宽和斜坡优先级要求。添加斜坡不等于允许随意移动、删除或削改既有合理坡道。
3. 整理材质、修复封装、编辑对象和脚本；材质和封装操作本身仍保持高度、水陆、坡形、玩法位图及连接关系。
4. 新图将预览定稿边界忠实转换为原生格式；已有图沿用冻结来源。添加斜坡的工具须核对实际差异，若额外改层界、改岸或改变坡外地形，则停止相关处理。现有工具的能力不等于已经自动满足边界保护要求。

## 地形冲突如何处理

净宽、完整占地、资源接入、全周岸线或其他严格规则不满足时，可调整本轮布局，或在保持两类边界的前提下添加斜坡并复验。无解保留失败／待确认并说明原因，不改边界换取通过，也不降低标准。

确需修改层边界或水陆边界时，结束当前可玩制作的相关步骤，返回[游戏预览制作](terrain_preview.md)修订并同步重绘；新预览及同版设计数据定稿后，再作为新的输入交接。符合边界保护要求的斜坡添加可直接在地图制作中进行，无须为此返回预览或重绘预览。

## 流程交接与验证边界

预览阶段交接定稿图片、同版边界／地形设计与坐标帧；可玩阶段交接基准身份、布局、新增斜坡方案与前后差异及未解决冲突。交付按[预览一致性验收](map_acceptance.md#游戏预览一致性如何验)核对边界保护，按[地形交接验收](map_acceptance.md#地形交接如何验)核对新增坡的几何、材质和导航；尚无完整自动边界保护门禁。

只更新 skills、规则或流程时，仅核对文本及引用，不运行地图构建、成品验收、预览重绘、版本递增、冻结源采用或安装，不修改现有地图或旧证据。
