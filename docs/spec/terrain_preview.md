# 公共游戏地形预览流程

**适用边界**：平滑、切层、拓宽、归并、水域整形、岸边归层等会改变层边界或水陆边界的设计及修订在本游戏预览制作阶段完成。预览及同版设计数据定稿后，按[预览边界保护](preview_terrain_lock.md)交接可玩制作；制作地图过程中不允许修改层边界、水陆边界，允许添加斜坡及其必要局部坡面和导航。需要改边界时返回本阶段，不先改游戏地图再重绘预览。

制作预览时，用户只需提供真实地形参考资料，并说：

> 以 xxx 为蓝图制作游戏地形图。

`xxx` 可以是地形原型或已定地图名。Codex 负责识别本次提供的资料、查阅 `docs/spec/九州大地命名.md`、准备参数并完成预览，用户无需另外编写配方、指定算法或重复确认文件名。只有参考资料缺失或无法确定对应蓝图时，才补充必要信息。

## 输入与命名

真实地形图、已有高程数据和可选的边界、水域资料均在制作时提供，不把某张图的地理范围、数据下载地址或名称写成公共默认。海拔切点采用下文的全国基础标准，允许按当地真实地形调整并记录。优先使用当前提供的蓝图，原始文件保存在该地图 `data/` 内供回查。

地图名称与系列展示名查阅 [九州大地命名](九州大地命名.md)。真实地形名用于本地目录和 CLI id，预览标题继续用“九州大地·地图名”。例如，输入“云南”或“层峦织彩”均保存到 `maps/云南/`，标题仍为“九州大地·层峦织彩”，不新建生成名目录。

- **提供高程资料**：使用公共 Rust 入口确定性地生成预览；有水域、主体轮廓和经纬度信息时一并读取。
- **只提供参考图片**：读取图片中的山岭、谷地、平原、水域和方向，以原图为视觉蓝图制作设计分层。使用图像生成或编辑能力时按 `imagegen` 技能处理原图，并保持三图同一取景。图中没有的测量高程不作为已知数据；无需要求用户另外寻找 DEM 或填写 JSON。

## 统一步骤

1. **识别蓝图并定名**：读取本次参考资料，按 docs 确定地图目录和展示名称。
2. **确定中心与游戏范围**：以蓝图主体为中心确定完整地理取景，可玩网格固定为 **800×800 格正方形**。保留现有地理取景，两个坐标轴分别重采样到 800 格；不按原取景比例保留矩形网格，也不裁掉主体。制作网格四周另留 20 格边框，因此含边框为 **840×840 格**。此处尺寸是地形格数，不是带图例 PNG 的像素尺寸。画面北朝上，保留主体完整轮廓。
3. **补齐整个游戏矩形**：主体边界是地理参考线；边界外、游戏矩形内的真实地形也属于游戏地形。仅裁掉游戏矩形以外的部分，不沿省界挖空、留黑或改成背景地形。
4. **整图统一分层**：整个矩形采用相同海拔／地貌判读、平滑、切层、层界整理、碎块合并和窄颈整理。省界不参与切层或区域合并。水域以蓝图为依据，按下文游戏水域整理规则处理细长条、分叉与碎水。
5. **映射设计高度**：采用全国基础海拔切点 200、500、1500、4000 米，映射游戏高度 210、280、350、420、700；第五层可按图采用 500–1000 的高山设计高度。各图保留 2–5 个实际存在的陆地层级，水域单独计算。局部调整遵守下文三条规则。第五层的禁行设计在预览中标明，实际通行留待之后制作地图落实。
6. **分别绘制原图与处理结果**：`source.png` 独立读取原始高程和来源水域，不做游戏平滑、切层、删湖、岸线整形或碎块归并；处理图呈现统一的游戏分层和设计水域；边界版使用完全相同的设计分层，额外画地理参考线和矩形游戏外框。边界不改变地形。
7. **核对并保存**：三图朝向、地理取景和画幅一致，主体完整入镜，矩形内没有缺失地形；分别核对原图与真实来源、处理图与设计数组，检查层高与分层对应。设计岸线可以与来源岸线不同，不能为使三图水域相同而修改原图。

## 从分层关系到实际过渡

预览按[地形交接规范](terrain_transitions.md)标明坡道、不可通行层界、连续水陆过渡与人工岸的设计范围，先处理层界抵岸、坡口靠岸及窄颈的联合空间，再分别整理各段。这里的固定层高、色块相邻和岸线描边只表达分层关系；推进可玩制作时须另落实全宽坡体、坡肩、端口及陆台到水底的真实剖面、材质和导航，不能把分层数组的硬高差直接当成定稿岸坡。纯预览记录预留和待验范围，原生判定按[地形交接验收](map_acceptance.md#地形交接如何验)衔接。

## 全国基础分层与局部调整

| 层级 | 真实海拔基础区间（含下限、不含上限） | 默认游戏设计高度 |
|---|---|---|
| 第一层 | 低于 200 米的陆地 | 210 |
| 第二层 | 200–500 米 | 280 |
| 第三层 | 500–1500 米 | 350 |
| 第四层 | 1500–4000 米 | 420 |
| 第五层 | 4000 米及以上 | 700，禁行高山设计 |
| 水域 | 以真实水域为依据的当前设计掩码，与陆地海拔分段分开 | 预览水底 130 |

以下三条适用于整个游戏矩形，省界不参与判定：

1. **不强求五层**：没有的高度层直接省略；整理后的小碎层并入相邻层。图例只显示实际保留的层及对应真实海拔区间，保留全国层号与对应游戏高度，不为凑数造山。
2. **不足两层时局部补分**：纯平原或高原地图可能全部落在一个区间，应按当地真实高程进一步划分，并记录调整后的阈值。公共实现依次尝试平滑陆地高程的 50%、40%、60%、30%、70% 分位点；优先选择经相同连片、碎块和窄颈整理后能保留两层的切点，映射为游戏高度 210、280。完全平坦或过于破碎、无法按真实高程补分的资料应明确报错，不虚构地形。
3. **高原不能整片禁行**：青海、西藏等地图应提高高山层门槛，让宽阔高原面保留为可玩台地，第五层禁行区主要留给突出山脊和山峰。公共实现以平滑后陆地海拔中位数达到 3000 米识别高原主体，将第五层门槛提高到原切点、90% 分位高程和中位高程加 750 米三者的最大值；第五层没有保留区域时直接省略，仍不足两层则按第二条补分。这是预览设计标准，不是地理学分区或实际游戏通行验收。

真实海拔先平滑再切层，并继续做连片整理，因此最终各格未处理的真实海拔可能跨越名义区间。原始真实高程保留不变。每张图的 `data/terrain-preview/report.json` 记录全国基础切点、请求切点、最终切点、调整原因、实际层号和各层面积。

## 交战路线与伸入地形整理

本规则同时检查台地层、陆地和水域，公共参数统一来自 [coordinate-pipeline.json](../../rules/coordinate-pipeline.json) 的 `terrain_shape`：

| 情形 | 当前要求 | 不足时处理 |
|---|---|---|
| 交战通行路线上的层、陆地、水域 | `combat_route_minimum_width_cells`：连续通行净宽至少 **10 格** | 就地适当拓宽补足，保持路线与两端接入连续 |
| 伸入相邻区域的细长层、陆地、水域 | `intrusion_minimum_width_cells`：有效主体与窄颈净宽至少 **5 格** | 将不足部分并入附近实际相邻的层、陆地或水域，整理连接与边界 |
| 赠送建筑 | `exclude_gift_buildings_from_intrusions: true` | 所有主、备用点及其他分支的完整建筑占地均须避开伸入区域，另选主体区域落点 |

格数按本图 Frame 的地形格计算；上述数值是**宽度**，不是面积、半径、PNG 像素或游戏世界单位。按实际移动域，沿通行主体、连接颈部和受阻断面测量扣除陡坎、岸线过渡、阻挡及实体占地后的净宽，不以中心可达、局部最宽处或总面积代替。交战路线与伸入区域重叠时，交战段执行至少 10 格的要求，不能按 5 格放行或通过归并切断交战路线；斜坡等已有更大宽度要求仍执行对应规范。

推进可玩制作且双方实际基地已确定时，按[对位路线与沿路布矿](resource_distribution.md#对位进攻路线与沿路布矿)落实通路，全部坡矿冲突按[斜坡优先级](ramp_clearance.md#斜坡优先级与冲突处理)处理。纯地形预览尚未定基地时只记录通路候选与待验范围，不据此虚填出生点或资源布局。

伸入区域包括台地细舌、窄颈半岛、尖细陆地尾部、水域支汊及同类深入邻域的细长部分。不足 5 格的部分就近接入实际相邻、归并后连续可用的层或水陆主体，记录归并目标依据，不跨大片地形串接远处区域。达到 5 格可按其他规则核对后保留；**达到宽度要求的伸入区域仍禁止摆放赠送建筑**，拓宽后仍属伸入地形的也继续排除。赠送建筑按合法朝向核对完整占地、出入口和接驳预留与伸入区域不重叠，不只检查航点中心。普通建筑与资源继续按自身完整占地规则验收，本节不另设统一建筑面积门槛。

保存修改前分层、水陆掩码及来源轮廓，逐处记录交战路线与伸入区域 ID、坐标、用途、原净宽、拓宽／归并范围、目标及前后证据。真实高程和原始地理资料保留；设计层级、水陆掩码及配套参考／蓝图同步调整，范围外地形保持，再从同版数组重绘图片。现有 `water_design_land_reference` 会保留参考陆地层级，`water_policy` 仅记录策略，不会自动执行本项拓宽、归并或赠送排除；局部调整须落实到实际输入并验证重生成结果。保留水体继续按下文单层包裹及全周岸线规则核对，移除的水域明确记录范围，不声称设计掩码未变。

原生渲染支持在 `water_design_land_reference` 中显式设置 `use_reference_water_mask: true`，同时回读已保存参考 NPZ 的设计分层和水域；省略或 `false` 时保持原有输入水域行为。参考高程、地理边界、840×840 网格、Frame 和设计高度须与当前来源一致，生成前校验不符即报错。该选项用于复现经审阅的设计结果，不会自动识别或修补细长地形。修订范围、归并目标及原始水域须另行留证。

按[交战路线宽度与伸入地形验收](map_acceptance.md#交战路线宽度与伸入地形如何验)提交记录。纯预览核对实际设计数组与空间预留，可玩候选另回读原生高度、导航、建筑与脚本；当前尚无上述三项的完整公共自动门禁。规范更新本身不自动编辑冻结成品或补写旧版通过记录。

## 水域显示

2026-10-28 用户要求现有六图去掉河流，仅保留海洋及面积较大的湖泊、水库。本轮以真实多边形轮廓估算的 **80 平方公里**为湖泊、水库保留门槛；这是可调整的游戏设计筛选值。面积按完整水体、扣除岛屿后计算，再裁到游戏矩形，不按裁后面积淘汰跨边界的大湖。来源筛选与游戏岸线设计分别记录；局部填合遵守下文规则，不以凑海战面积为由任意扩大湖泊。

- 海洋使用真实海洋多边形，避免把河道、低于海平面的陆地或高程异常点误判为海；本轮再用半径 3 格的开运算清理伸入内陆的细窄水道，保留开阔海域。
- 河流中心线与河道水面不加入预览；海洋数据中的海湾、宽阔河口按海域保留。
- 将满足面积门槛的湖泊、水库多边形与海洋掩码合并为来源水域，再进行游戏水域整理，不再叠加河流线；当前设计结果写入 `water_mask`，来源掩码另行保留。
- `preview.png`、`preview--line.png` 及已有中心标点图采用同一当前设计水域掩码。`source.png` 采用独立的原始高程和来源水域，保留已有资料中的真实轮廓，不应用上述筛选、开运算或游戏岸线整理。筛选前与整理前的参考 NPZ、水域和河流资料保留供回查。
- `parameters.json` 的 `water_policy` 和生成报告记录筛选规则；`water-policy.json` / `water-report.json` 保存各水体的估算面积、取舍及格数。面积来源是参考矢量的估算值，不称为实测或法定面积。

### 游戏水域整理

游戏地形预览默认避免细长条、窄颈分叉和零散碎水。相邻水体或同一水库的支汊，能够局部填合的优先合并并圆整为宽阔、闭合的连片水面；无法合理合并的细小水域并入附近实际相邻的陆地层，并整理局部层界。按当地地形就近处理，不跨越大片陆地串连远处湖泊，也不要求全图水域合成一块或画成环形。

水陆两侧对称检查：伸入水域的细长陆地、窄颈半岛和尖细尾部同样需要整理。优先就近收拢、圆整或拓宽成宽阔主体；无法合理保留的细条并入周围水域。按最终游戏框检查，保留真实高程与来源轮廓，记录设计岸线的变化。

#### 小水域的单层包裹

保留的小水域跨越多个陆地层时，先统计**调整前**完整岸线与各层的接触长度，选择接触最多的陆地层作为归属层；将水域周边整圈陆地统一划入该层，局部外移、绕开水域整理层界，使水域完整包裹在一个陆地层内，便于连续水陆连通。水面仍保留为水域，不将水体填成陆地，也不把水底层号当作归属层。

接触量按共享水陆边的实际长度累计；方格网按四邻共享边统计，非等距网格按各轴格长换算，仅对角接触不计。统计须覆盖全周及存在的内岸，不以周围各层面积、层高或一处最近点代替。并列最多时，结合局部层界连续性选定其中一层并记录理由。小水域的适用清单、尺度依据及岸边调整范围按本图确定，不新增统一面积或岸带宽度阈值；开放海域和跨游戏框水体单列说明适用性，不擅自按内湖补闭合。

整理后逐处核对全周陆地侧只接触归属层，其他层界不再切到岸线，并与该层主体连通，不能只重涂预览色块。保存水体 ID、调整前各层接触长度、归属层、修改范围及前后分层证据；存在多个适用小水域时逐个处理。归属统一不代替缓坡及双向通行验收，仍须满足下文全周要求。

小岛和小水域采用**整圈边界连续、可双向跨层通行**的设计，所有边界位置都能通向相邻层级；只留少数坡口、单一出口或仅验证中心可达，均不满足该要求。预览制作阶段在本图参数和同版设计数据中明确完整岸线的过渡范围、岸坡高度及连接关系；可玩制作保持层边界、水陆边界，允许添加斜坡，逐段核对宽度、坡度、阻挡和导航。新增岸边斜坡不得改变水线、归属层或水陆掩码，也不能替代整圈连续过渡。预览色块接触及二维连片检查只说明设计关系，不替代实际游戏通行验收。

整圈岸线按[公共交付验收](map_acceptance.md#整圈岸线如何验)列为必检项：列全适用水体、岛屿及内外边界，逐段留存覆盖统计、实际测量和双向连接结果。公共自动门禁尚未完整覆盖，缺少逐段证据须记待核验，不可用布矿、坡口或少数路线通过代替。

- 修改前保留完整原始输入和来源水域掩码；真实高程、地理边界、取景和北向保持一致。设计岸线与来源轮廓分别记录，整理后不再声称当前水域严格等于原始湖海轮廓，也不把新增水面格数称为真实面积。
- 合并、填凹和圆整方法按本图选择；交战路线及伸入地形的最低净宽执行[公共整理规则](#交战路线与伸入地形整理)，其余面积和处理半径按本图尺度确定，不把单图的水体数量、坐标或数值阈值写成公共要求。数值预览先整理输入 `water_mask`，再用原生 `terrain-preview` 生成；当前 `water_policy` 仅记录规则，单独填写不会执行整形。
- 仅修改已有预览水域时，保存整理前的 `terrain.npz` 和 `report.json`，在本图参数中配置 `water_design_land_reference` 的 `terrain`、`report` 相对路径（以 `data/terrain-preview/` 为基准）。原生生成沿用原有陆地层级和最终海拔切点，只将移除的水域就近接入相邻陆地层；核对仍为陆地的原格层级不变，避免水域变化触发整图分位切层或碎层传播。
- 本轮涉及小水域单层包裹时，允许按上述规则修改已记录岸边范围内的陆地层级，范围外仍保持原层级及分层切点。当前 `water_design_land_reference` 会保留原陆地层级，`water_policy` 仅记录策略，均不会自动执行岸边归层；须将已核验的局部调整落实到实际分层输入及相应参考中，保存调整前后快照并验证重生成结果。
- 本轮涉及交战路线拓宽或细长伸入部分归并时，可在已记录范围内调整设计层级及水陆掩码，同步参考输入；范围外保持原地形，不沿用“仅改水域、原陆地层级全不变”的口径。
- 规则与结果保存到本图 `data/terrain-preview/`，同步更新参数、水域统计和核对记录。游戏分层图及已有中心标点图从同一设计掩码重绘，原图继续使用独立的真实来源。
- 核对残留碎水、细长分叉与窄颈，确认保留水面宽阔连片、移除水域已接入有效相邻陆地层，局部层界衔接正常，原始资料和同取景条件得到保留。明确要求原样展示真实岸线时遵从当次要求。

## 高程资料的公共执行入口

Codex 根据当次资料执行，例如：

```sh
cargo run --release --locked -- terrain-preview <蓝图原型或已定地图名> <提供的高程NPZ>
```

命令在完整地图配方建立前即可使用，不依赖 `config.json`、`layout.json`、八个出生点或版本文件。命名从 docs 动态读取，不修改 `maps/.default`。优先读取 `maps/<真实地形名>/data/terrain-preview/parameters.json`，兼容已有的根目录 `preview.json`；没有配置时采用全国基础切点并执行上述三条规则。预览重做不改动可玩地图的配方、定稿分层数组或制作源。`map_id` 记录真实地形名，`map_name` 保留生成展示名；设计坐标声明中的缓存路径相对工程根目录。

NPZ 按第 0 行为北排列，包含：

| 数组 | 含义 |
|---|---|
| `elevation_m` | 必需，二维真实高程 |
| `water_mask` | 可选，同尺寸 0/1 当前设计水域掩码；来源与整理规则分别留档，缺省按高程不高于 0 判定水域 |
| `land_mask` 或 `inside_province` | 可选，蓝图主体的 0/1 轮廓，用于取景和参考线，不裁切游戏地形 |
| `bounds_wgs84` | 可选，完整输入网格的 `[西, 南, 东, 北]` 经纬度范围 |

命令自动选择贴近主体的地理范围，保持完整地理取景，将宽高分别重采样为固定 **800×800 格**正方形。高程双线性采样，边界与水域用最近邻采样，整图统一生成游戏分层。报告的 `game_cells` 为不含边框的可玩范围，`size_policy` 记录正方形要求、800×800 格尺寸、独立轴重采样及来源尺寸，制作网格另加四周各 20 格边框。原始参考拷贝、地形数组、参数、图像校验和及范围记录保存在 `data/terrain-preview/`。原有成品构建的 `preview` 阶段继续用于布局预览，与这里的制作前纯地形流程分别使用。

