# 布局规划与诊断

工具复用出生组、坡口、分级资源、EA 完整占地和生产接入的正式规则；本页只描述执行方式。参数含义仍查[公共约束总表](map_rules.md)。现有地图不会因工具升级而自动重建、重新验收或改写预览。

## 输入身份与阶段顺序

`build`、布局预检、布局搜索及成品编辑在尝试开始时记录输入清单与 SHA-256，阶段前后检查漂移。清单包含选定配方、布局、蓝图、资源计划、冻结包、边界保护资料、预览、规则、模板和实现源码。运行期间编辑输入会停止该次尝试，不悄悄沿用新旧混合输入。版本状态与生成目录不当作固定输入。漂移检查检测修改，不替代版本库或输入备份。

新图生成地形前只读验证 Frame，不在预检中准备或覆盖坐标声明。地形缓存绑定选定蓝图字节、几何参数、声明布局与最终派生快照；缺少绑定或与当前输入不同，须重新执行 terrain。冻结图仍以配置指定的完整原生来源为准。map 组装在纹理和封装之前检查最终实际对象，避免再读旧布局检查另一套坐标。

推荐顺序是定稿预览及设计资料、确定出生/路线/坡道、快速诊断、规划候选、审阅并显式采用布局、完整构建、独立验收与发布。出现冲突先保留诊断，调整本轮授权范围内的布局；不临时缩小完整占地或取消约束来取得通过。

## 两级预检

```sh
cargo run --profile authoring --locked -- check-layout --map <id>
```

此命令写 `assets/<id>/<发布名>/layout-preflight.json`，不生成纹理、不改布局。粗预检读取实际 Frame、明确的队伍/路线/矿物身份及原生导航，统计连通分区、家矿同面、资源阶段和两队面积事实，并做有界候选采样。

状态分为 `diagnostic_clear`、`hard_conflict`、`search_inconclusive`。采样找不到点只表示该次采样未找到；队伍面积差记录为设计审阅事实，不能借粗预检自动创造规则例外。报告明确列出未覆盖项，粗预检通过不授权原生组装或交付。

完整原生候选检查由组装及搜索共享，读取最终实际对象、脚本主备/条件分支、旋转完整占地、矿盘与矿场、坡口、重试规则、建筑朝向和生产接入。失败尽量给出冲突双方的原生对象 ID、角色、坐标及规则；无法定位的错误明确标记，不伪造坐标。前置几何通过后，再叠加全部功能预留计算主次路线及基地外侧接驳净宽。

净宽采用障碍相交格保守栅格化和精确欧氏距离场，扣除格半对角线得到下界；保存实际路径、窄点和相对声明路线的偏离。下界未达标不证明整张地图无解。地形界面连续性、设计路线直接性与独立交付判定仍按[交付验收](map_acceptance.md)处理。

## 有预算的布局候选

```sh
cargo run --profile authoring --locked -- plan-layout --map <id> \
  --budget 100000 --time-limit 60 --seed 0 \
  --candidate-limit 64 --radius 56
cargo run --profile authoring --locked -- plan-layout --map <id> --resume
```

默认报告为 `assets/<id>/<发布名>/planning/plan-layout.json`；可用 `--output <报告路径>` 指定。相邻 `.cache.json` 与 `.checkpoint.json` 保存绑定输入的验证缓存和搜索进度；恢复时保持种子、候选数量和半径等指纹参数相同；节点预算和时间预算可以调整。报告不是可直接覆盖正式输入的布局文件；只有人工审阅并明确采用后才能进入生产。

搜索针对已声明的矿、中立建筑和实际已有赠送航点，保护基地、坡道及未解析身份。候选域为确定性的有限邻域，优先当前位置，在主备优先级内按候选域数量排序并做局部回退；每个候选复用正式原生检查。不会凭空设计出生点、主次路线或新增坡道。缓存按原生来源、完整布局、规则、实现源码、随机种子和候选参数绑定；缓存通过仍重新检查，断点拒绝越域或移动受保护对象。

`candidate_ready` 必须有完整正式检查覆盖且无未解决项；时间预算在正式检查调用之间判断，单次检查不会被强制中断。`search_exhausted` 表示节点预算、时间预算或有限候选域用尽，不等于全局无解。预算或有限候选域耗尽时保存报告、排除原因和断点；输入、指纹、输出保护或 IO 错误以实际已落盘记录为准。搜索不会自动构建、升级版本或安装。

## 局部原生编辑范围

使用 `NATIVE_CELL_EDITS` 修改格点时，必须另由 `NATIVE_CELL_EDIT_SCOPE` 指向带来源哈希的范围声明。范围文件绑定完整源包成员、同版设计分层/水域掩码、允许修改格与每条新增坡道掩码；不再接受没有边界依据的任意高度清单。

```json
{
  "schema_version": 1,
  "source": {"path": "authoring/source.zip", "sha256": "<64位SHA-256>", "member": "<实际.map成员名>"},
  "design": {"path": "authoring/design.npz", "sha256": "<64位SHA-256>", "layer_key": "layer_class.npy", "water_key": "water_mask.npy"},
  "allowed_cells": {"path": "authoring/allowed.npy", "sha256": "<64位SHA-256>"},
  "slopes": [{"id": "R1", "layer_pair": [1, 2], "raw_range": [5376, 7168],
    "mask": {"path": "authoring/r1.npy", "sha256": "<64位SHA-256>"}}]
}
```

掩码为完整原生 `[height,width]`、北向在上的 NPY 0/1 数组；设计层标签为水域0、陆地正整数。`raw_range` 是原生 u16 高度范围。坡面必须在允许格内，保持设计分层与水域边界，禁止范围外变化；材质编辑另须 `materials.mask` 声明，只有明确 `clear_blends: true` 才可清理混合。所有输入先验证完再应用，失败不留下半改地图。冻结源身份、原生区块和本轮无关内容继续受保护；该范围声明不替代新增坡道设计审阅。

## 尝试计时与证据

每次尝试保存 `work/runs/<id>/<run-id>.json`，阶段开始即落盘，成功、失败和正常展开的中断均记录状态及耗时。每阶段输出 `[计时]`；失败也保留已完成阶段和错误。可以设置 `RA3MAP_TASK_ID` 将同一任务多次尝试关联起来。缓存命中另记事件，不用旧执行时间冒充本次耗时。

这些数字只包含 CLI 进程，不包含 Cargo 编译、对话、人工设计或进程外操作；并行尝试的耗时不能相加当墙钟时间。强制终止或断电可能留下 `running`，需要结合进程状态判断，不能宣称所有系统中断都能捕获。

```sh
cargo run --locked -- timing-summary --map <id>
cargo run --locked -- project-status
cargo run --locked -- check-docs
cargo run --locked -- archive-evidence --map <id>
```

`timing-summary` 按任务 ID 汇总全部尝试与失败阶段，合并重叠进程区间，单列未测量间隔和未结束记录；阶段累加包含重试，不冒充整个任务的墙钟时长。状态清单从实际配置及文件生成；文档检查定位活动入口/规范/技能的本地 Markdown 死链。显式证据归档把本次可取得的报告与索引写到 `histories/<版本>/evidence.zip`，标明候选哈希是否匹配、是否未绑定。旧报告和未绑定报告保留其真实身份；工具不生成独立通过结论。是否允许交付继续由[结构化独立验收](map_acceptance.md#结构化独立验收门禁)决定。
