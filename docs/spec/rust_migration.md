# Rust 迁移与数据配方

当前可执行工具链为原生 Rust，旧 Python 配方不再执行。本文维护配方字段与输入路径；当前保留地图和版本见[当前状态](../SESSION_STATE.md)，生效规则与验收覆盖见[公共约束总表](map_rules.md)。

制作分为声明式蓝图生成与完整原生来源编辑两条输入路径。当前河南通过 `COORDINATE_PIPELINE` 读取 `authoring/source.zip` 和 `authoring/layout.json`，保护实际高度、材质、位图、身份及本轮无关脚本；完整来源不提供验收豁免。坐标编辑、严格验收及采用来源步骤见[通用坐标制作流水](coordinate_pipeline.md)。

## 从过程式配方到声明式数据

当前使用显式 `layout.json` 声明布局，不执行旧配方的自动搜索或历史复现入口。预览定稿后，制作地图过程中不允许修改层边界、水陆边界，允许添加斜坡。新图转换预览设计并落实本轮显式新增坡道；已有图沿用完整冻结原生来源，通过受控新增方案写入必要局部坡面高度与导航。可玩构建不借层高重算、海深重设、改岸或平台铺平改变边界。工具默认会改变边界时停止相关处理并报告，确需改边界则返回[预览制作](terrain_preview.md)。

新蓝图路径改变布局应修改配方指定的 `layout.json`；冻结成品路径的受控坐标修改使用 `authoring/layout.json`。已有合理坡道继续保护，新增坡道须使用与原生候选一致的显式方案，按[成品编辑衔接](coordinate_pipeline.md#成品编辑后的衔接)验收，不能只改冻结布局中的坡声明而不更新原生高度。旧版自动搜索、DEM 下载、底图抓取和一次性逆向研究脚本没有作为 Python 兼容层保留；制作前预览改用 [公共地形预览](terrain_preview.md)，由 `terrain-preview` 接收当次提供的高程资料，参考图片则按制作技能解释为设计蓝图，不自动套用某张地图的数据源；如需研究其历史实现，可查看迁移前的 Git 历史。已有 DEM/地理输入文件保留，新蓝图路径直接读取配方指定的分层输入。

## config.json

`SCHEMA_VERSION` 为 1。核心字段：

| 字段 | 用途 |
|---|---|
| `MAP_NAME` / `PUBLISH_NAME` | 游戏名称前缀 / 可选发布名称前缀；不决定本地目录 |
| `RESOURCE_ID_SEED` | 可选 uint32，固定资源命名空间；目录和 CLI 改名不改变资源身份 |
| `GRID` / `GRID_HEIGHT` / `BORDER` / `CELL` | 全图宽度 / 可选高度（默认等于宽度） / 边框格数 / 世界单位换算 |
| `Z_SCALE` / `WATER_Z` | uint16 高程换算 / 水面高度 |
| `TEMPLATE` | `templates/` 下的地图骨架 |
| `RULESET` | `rules/<RULESET>.json` 脚本与阵营规则 |
| `LAYERS` | 地图目录内的蓝图 NPZ，默认 `layers.npz`；实际路径以当前配方为准 |
| `LAYOUT` | 地图目录内的布局 JSON，默认 `layout.json`；实际路径以当前配方为准 |
| `COORDINATE_PIPELINE` | 可选完整原生来源、可编辑布局、来源对照与局部策略；启用后保留输入内容并执行当前严格检查 |
| `RESOURCE_DISTRIBUTION` | 所有可玩图必备的对位主次路线与阶段计划；结构和配额见[资源规则](resource_distribution.md) |
| `DELIVERY_ACCEPTANCE` | 可选本图相对路径，指向匹配最终候选的结构化独立验收；默认读取同版 assets 下记录，缺失时拒绝发布／安装／采用源 |
| `SPAWN_PLACEMENT` | 可选出生点策略对象；所有输入与增量编辑均严格零问题，不能关闭检查或继承来源问题 |
| `HEIGHT_PRESET` / `LAYER_M` | 标准高度预设 / 陆地层高 |
| `TEX_SET` / `LAYER_TEX` | 纹理资源与层纹理映射 |
| `MAP_STR_*` / `PREVIEW_*` | 游戏文本与预览文案 |
| `TERRAIN` | 现有地形格式／参数的解析字段；可玩制作须保持设计层边界、水陆边界，显式新增斜坡只作用于确认的局部坡面与导航，不借默认量化、改岸或铺平台改变边界 |

`GRID` 和可选 `GRID_HEIGHT` 须为 8 的倍数，边框必须小于两边各自的一半。蓝图 `base_z` 按 `[GRID_HEIGHT, GRID]` 保存，未配置高度时仍为方形。地图 id 使用真实地形名（当前为 `河南`）；制作资料和成品分别位于 `assets/<id>/<生成发布名+版本>/`、`dist/<id>/<生成发布名+版本>/`，ZIP 文件名与游戏内容继续使用生成发布名。地图 id、发布名和配方路径必须留在工程范围内。当前原生地形路径使用 `use_v11_layers: true` 与 `v11_plain: true`；已包含斜坡的定稿图使用 `v11_baked: true`。

当前必要蓝图以 `LAYERS` 明确声明；根 `layers.npz` 与所选定稿蓝图逐字节一致，不由 `.map` 回读或重新量化生成。版本切换需核对 `LAYERS`、对应 `LAYOUT` 及根镜像；冻结成品继续读取完整 `authoring/source.zip`。完整目录约定见 [蓝图与版本资料](blueprint_versions.md)。

同一张地图改目录或 CLI 名称时保留 `RESOURCE_ID_SEED`；复制配方创建另一张地图时删除该字段，由新的 id 派生资源命名空间。

新蓝图路径的纹理噪声使用确定性的 MT19937 取样和种子，纹理与地表装饰由 Rust 重新生成。冻结成品路径则读取并保留来源原生纹理与位图，不自动套用新的纹理规则。

## layout.json

所有坐标均为全图格坐标，x 向东、y 向南。下列字段说明用于新蓝图路径的布局；`objects` 定义实际游戏对象，其余集合用于地形构造与验收，调整资源或出生点时须同步修改对应集合与对象。冻结成品路径以 `authoring/layout.json` 的原生对象身份与顺序为准，从实际对象派生矿位等分类清单，无需手动重复同步。可玩制作允许添加斜坡，新增 `ramps` 声明必须与实际候选坡面及局部导航一致，层边界、水陆边界保持基准。

- `base_cells`：按人类 1–6、固定 AI 7–8 排列的最终出生点；对置侧别及与两矿同面空间由[公共出生点验收](spawn_placement.md)检查。
- `base_pad_cells`：旧平台参数的格式识别字段；可玩制作不使用它铺平地形。
- `ore_cells` / `ore_angles`：最终矿位和内部坐标系的矿口角度。对象中的游戏朝向使用相反 y 轴。
- `derrick_cells`、`post_cells`、`garage_cells` 等：资源和中立建筑位置。
- `city_cells`：定稿城市纹理中心。
- `ramps`：既定及本轮新增斜坡的中心、尺寸、低／高层及上坡向量；既有合理坡道保留，新增坡面允许必要局部高度及通行变化，不修改设计分层或水陆边界。
- `objects`：类型、版本、格坐标、角度、道路类型和有类型的属性表。bool/int/float/ASCII/Unicode/unknown 属性分别保留其磁盘类型。

`ramps` 的坡宽、两层连接、端口与全宽检查按[山地斜坡规范](mountain_ramps.md)解释；`face` 布局同样适用。坡体、坡口及完整引道按[斜坡优先级](ramp_clearance.md#斜坡优先级与冲突处理)先于矿位确定，布局中的矿区保护不能成为保矿改坡的依据。

新蓝图构建在 `map` 阶段自动调用与 `polish-textures <成品ZIP> --map <id> --bump` 相同的选材和混合函数；冻结成品构建保留来源材质，应用当前规则需显式运行后者。主纹理、变体、禁用材质与平铺要求只在[纹理规范](terrain_texture_rules.md)维护。允许的 `TEXTURE_PROFILE` 值见下方[格式保护](#当前严格验收与格式保护)。

纹理后处理保留高度、对象、脚本和通行／建造位图，已有成品保留实际布局快照；最终材质编号整理与加载声明同步按[纹理清理](terrain_texture_rules.md#公共纹理清理与数量上限)执行。

第二座产能的路径点与脚本必须对应。修改出生点时，也应检查 `dual-*` 路径点及固定 AI 建造场。成品回读会检查这些路径点是否存在。编辑地图内容后递增版本，再重新构建和验收。

## 脚本规则模板

`rules/` 是已定稿玩法的可复用数据模板，包括公共脚本、固定 AI 科技、第二座产能和按图选择的进攻规则。模板中的 `asset` 与 `command` 使用名字；Rust 在构建时解析、检查并链接为当前地图字符串编号，不依赖模板中的数字编号碰巧一致。

容器前缀和叶子指令正文保留十六进制字段，以无损保存 SAGE 各版本的未知字节。`children` 表达层级，`command` 表达动作/条件的内部名字。阵营与队伍属性也经过原生解析和重新编号。

玩法由当前 `RULESET` 确定。新图选择并明确维护脚本模板，不能通过脚本模板或未执行字段绕过公共布局、资源及发布门禁。

`common-T0.5.1` 是当前通用模板，脚本、分组、条件和启用状态由模板及本图实际原生来源确定。它不额外注入电脑现金显示、电脑主动进攻、位置分队或四人落座。固定 AI 的对象身份、阵营和外交按当前脚本绑定，不能据航点顺序猜测。

通用脚本的赠送策略统一读取 `common-T0.5.1.json#/production_placement`，包括使用独立玩法模板的地图；占用重试、水陆、朝向和完整预留只在[赠送规范](production_placement_fix.md)维护。新蓝图 `map` 阶段生成相应选址与脚本；冻结成品构建保留已有脚本和航点并回读校验。已有成品通过 `repair-production --map <id> --bump <源ZIP>` 显式更新，保留原触发条件、阵营与归属，随后按[成品编辑衔接](coordinate_pipeline.md#成品编辑后的衔接)采用新源并补齐资料。

模板的 `spawn_waypoints` 声明 31 个超武、电厂航点的名称、所属出生位（1–8）和占地半径（格）。`script_spawns` 根据每张图的定稿出生点，在公共生效搜索范围内寻找平坦、可通行、可建造的陆地，并避开资源、建筑、装饰、基地及 `dual-*` 产能点。它只追加航点，不修改地形、矿位或原有对象；找不到安全落点会使构建失败。成品回读再次检查占地与脚本航点、控制目标引用。坐标报告写入 `assets/<地图>/<生成发布名+版本>/script_waypoints.json`。采用模板的配方需提供 `MAP_STR_INFO.GameStart` 文本。

需要按席位规划时，可用 `SCRIPT_SPAWN_RADIUS_BY_SEAT` 明确候选搜索范围；范围不是距所属基地的合格线。赠送产能仍按[所属基地原则](production_placement_fix.md#赠送生产建筑靠近所属基地)优先就近，完整占地与实际接入同时满足。

## 当前严格验收与格式保护

所有非 `TERRAIN_ONLY` 地图都必须提供当前两矿分级计划。出生点、完整占地、坡形、坡口及静态通路不继承原来源问题；`SPAWN_PLACEMENT_REFERENCE`、`RAMP_CLEARANCE_REFERENCE` 和 `legacy` 坡形／纹理参数均拒绝。`RAMP_PROFILE` 缺省及唯一生产值为 `mountain`，`TEXTURE_PROFILE` 缺省及唯一生产值为 `classic-natural`。

[官方最终场景与 XML](official_resource_pipeline.md)在生产入口默认严格检查；显式诊断仅用于只读分析，不能授权构建、发布、采用源或安装。完整原生包、既有发布证明、原生字节未变或所选脚本模板均不构成规则豁免。

原生编解码继续保留未知区块、合法原始属性类型及必要资源身份；字符串表按 ID 严格倒序写出，并校验容器规范编码和确定性压缩。官方格式片段与合成局部夹具只用于这些格式回归，不提供旧可玩地图的发布通道。

版本、回滚和可选安装按[流水事务](coordinate_pipeline.md#制作输入)执行；常用 CLI 入口见[项目首页](../../README.md)。

## 新增地图

复制一份配方目录时，先移除原图的 `COORDINATE_PIPELINE` 来源配置，避免继续引用别图的冻结成品；删除原 `RESOURCE_ID_SEED` 以派生新地图的资源命名空间。接入预览阶段定稿的分层、水陆边界及已有坡面、岸坡和高度数据，配置忠实转换方式；按[专业交接顺序](map_skills_checklist.md#共用执行顺序)在保持边界的前提下选择出生组和路线，明确需添加的斜坡与完整引道，再落实资源与 `RESOURCE_DISTRIBUTION`；选择匹配固定 AI 水陆位置及进攻规则的 `RULESET`。构建不会再次自动搜索或移动布局点；不合格的建造盘、出生平台或斜坡会使验收失败。新图定稿并核对完整原生包、同版 `source/layout.json` 和适用验收后，可运行 `adopt-coordinate-source` 启用冻结成品模式。

`version.json` 为每张图独立维护。只有改变地图内容才递增版本；保持 `.map` 字节一致的纯工具链重构不递增版本。
