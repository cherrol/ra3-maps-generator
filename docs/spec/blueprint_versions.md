# 蓝图选择与版本资料

本地地图 id 使用真实地形名；当前工程仅保留河南当前版的可玩配方、完整来源及必要制作输入。新图、完整来源编辑和重新封装均按当前两矿家区及严格零问题规则验收，不恢复已删除的旧成品、旧规则或历史发布入口。

## 当前选定蓝图

`LAYERS` 指定蓝图 NPZ，路径相对本图目录，默认 `layers.npz`。输入包含 `base_z`（`GRID_HEIGHT × GRID`）及 `z_scale`；`LAYOUT` 指定配套布局。实际路径以当前 `config.json` 为准，不根据版本目录名称猜测输入格式。

根 `layers.npz` 始终是当前选定蓝图的原字节镜像。选用或迁移输入时完整复制原字节，不重新编码 NPZ、不改变数组类型或比例、不从 `.map` 回读生成，也不把预览缓存直接改名为蓝图。

当前地图日常制作读取 `COORDINATE_PIPELINE` 指定的完整 `authoring/source.zip`、可编辑布局和来源对照。它们保护原生身份、本轮无关地形、材质、位图和脚本；按[边界保护与斜坡添加](preview_terrain_lock.md)允许新增斜坡的必要局部高度／导航变化，层边界和水陆边界保持不变。完整来源不是跳过当前规范的依据。

## 构建事务

构建在写入版本或产物前预读选定蓝图。构建阶段、验证与根镜像同步属于提交前事务；失败恢复此前版号及根镜像，只清理本轮新建产物。当前完整来源、布局及其他地图的输入不得被失败操作覆盖。

可选安装在本地构建提交后执行；安装失败报告“构建已完成，安装失败”，保留已提交成品和镜像。增量发布同样先提交本地成果再安装，安装失败报告“发布已完成，安装失败”。采用源只保存已通过当前全部适用验收的完整候选，不能把现有问题写成新基准后放行。

## 制作资料与版本归档

```text
maps/<真实地形名>/
  config.json
  version.json
  layers.npz                         当前所选蓝图的原字节镜像
  authoring/source.zip               当前完整原生制作源
  authoring/layout.json              当前可编辑布局
  authoring/resource-distribution.json
  authoring/coordinate-id-map.json
  histories/<当前版本>/              实际保留的同版制作资料
  data/terrain-preview/              独立预览设计帧及资料
```

只记录实际存在的输入及同版资料，不补造缺失版本。活动引用不得指向已删除的旧配方或旧成品；迁移必要输入时同步配置、布局、方案、测试、白名单及文档链接，再按[可复现构建](reproducible_builds.md)验证干净检出。

每个实际发布版本保留对应配置、完整源、布局、坐标编号对照、方案和验收证据；原始 ZIP 保存完整字节。`authoring/coordinate-id-map.json` 表示当前原生身份，版本对照只能引用仍保留且实际存在的资料。目录整理和纯工具链变化不改变地图字节时，不递增地图版本。

布矿、对位路线、坡口、交战净宽、赠送完整占地、生产建筑靠近所属基地、中立建筑选址、整圈岸线、热点双方路程及全部建筑／矿脉朝向按[公共交付验收](map_acceptance.md)随版留档。自动检查和独立测量分别记录，失败或待核验项不能通过来源更新消除。

[地形交接](terrain_transitions.md)的分段清单、剖面、导航、材质混合与局部外观证据绑定同版候选随版归档；规则修订后旧审核须补查新判据再重新绑定，不能只改修订号。冻结重建仍核对完整游戏文件，保留已验过渡。

## 镜像与原生输入核对

根镜像与 `LAYERS` 原件须逐字节一致；大小相同、尺寸相同或画面接近均不能替代。更换输入时同步 `LAYERS`、配套 `LAYOUT` 和根镜像。`use_v11_layers`、`v11_plain`、`v11_baked` 是现存算法字段名称，不提供旧地图来源或旧规则兼容模式。

预览 `terrain.npz`、蓝图及 `assets/.../source/terrain.npz` 分别管理，生成后的缓存不回写为根蓝图。原生格式解析与官方片段回归继续保护未知数据，但不构成任何旧成品的制作、验收或发布通道。
