# 脚本功能分类

脚本按功能分为开场与显示、计时、经济与开矿、阵营与基地、生产与科技、进攻、外交、奖励和地图事件。每项功能都需要明确作用位置、触发条件、前置状态和停止条件。

当前规则包含开场与音乐、游戏计时、基础 AI、阶段收入、中立建筑探索、生产补充、科技和奖励等分支；具体执行对象与启用状态由各图规则决定。公共赠送建筑另有主备落点、占用重试、水陆占地和朝向约束。功能目录中列出的其他方案属于可选或历史功能，不会自动装入地图。

**当前未启用独立分钟进攻。** 电脑现金侧栏、按位置脚本分队和四人强制落座也不是当前公共默认行为。已有图继续使用其定稿玩法，整理说明不会改变脚本、外交或地图内容。

## 1. 开场、音乐与雷达

| 功能 | 触发与依赖 | 用途边界 |
|---|---|---|
| 开场提示 | 地图初始化完成后显示一次 | 说明当前地图规则，不承担发钱、建造或开启 AI 的作用 |
| 音乐播放、切换、重播与停止 | 开局、曲目结束、计时或地图事件 | 单次播放与循环重播要分开，避免重复触发多个音乐分支 |
| 雷达与视野 | 指定位置、玩家状态或任务阶段满足条件 | 玩家雷达、AI 雷达和全图视野是不同能力，不能视作同一开关 |
| 游戏时间显示 | 初始化计时后持续更新 | 显示经过时间，不等于启动全部科技或进攻计时器 |

当前规则包含开场、音乐和游戏计时。雷达、全图视野与镜头控制是否启用，须由相应地图功能明确决定。

## 2. 计时与阶段调度

计时负责打开或关闭其他功能，本身不代替建造、升级和进攻条件。常用操作包括设置计时器、检查 `TIMER_EXPIRED`、延长计时、重置周期和停止计时。

- **全局计时**：以开局为共同起点，安排经济、科技或奖励阶段。
- **延后计时**：在前一阶段完成后再加一段等待，错开补贴或建造。
- **独立设施计时**：每座兵营、重工或船厂分别安排升级、生产与关闭窗口。
- **周期调度**：每次先取得本轮状态，再执行判断，最后重置计时；不能重复使用过期计数。

`ENABLE_SCRIPT`、`DISABLE_SCRIPT` 控制脚本是否继续评估，`CALL_SUBROUTINE` 调用子程序。一次性初始化、持续检查与子程序要区分；初始关闭的阶段脚本可以在满足条件后打开，并不必然是废弃功能。

## 3. 经济与开矿

| 方案 | 触发与依赖 | 用途边界 |
|---|---|---|
| 金钱显示 | 读取指定玩家当前现金 | 只显示，不增加收入；显示对象与发钱对象可以不同 |
| 分拍补贴 | 按时间、阵营和座位分批发放 | 起步补贴与后续补贴分开，避免每轮都重复领取一次性资金 |
| 阶段收入 | 根据阶段条件切换收入档位 | 达到下一阶段才启用对应档位，不能同时无条件运行所有阶段 |
| 矿场驱动收入 | 检查矿场数量、归属或经济状态 | 与固定时间补贴不同，不能把“有矿位”直接视为“已有矿场” |
| 中立资源探索 | 满足探索条件后寻找或处理目标 | 与资源在地图上的摆放分开，不自动重排矿、油井或科技建筑 |
| 扩矿状态机 | 选定目标、前往矿区、展开或建造、确认完成后关闭本轮 | 需要可达路线和合格占地，不能持续对已完成目标重复下令 |
| 扩张后补电 | 经济或建筑数量增加后检查电力 | 电厂补充与矿场完成分别判断，不以展开指令代替完成状态 |

当前规则保留阶段收入和中立建筑探索分支。分拍补贴、矿场驱动收入和多圈扩矿是可选择的设计方式，不能据此认定所有位置均具备自动扩矿。

开矿还要区分勘探车、采矿车、矿场核心与矿场建筑：移动载具、展开和最终矿场成立属于不同状态。人类位置、可选 AI 位置和固定 AI 位置的资格条件也应分别检查。

## 4. 阵营识别与基地

先确认玩家控制类型、阵营与基地状态，再进入相应建造分支。可选位置只有在满足 AI 条件时才运行电脑发育；固定 AI 的归属和阵营由地图规则明确指定。

主要操作包括识别阵营、找到对应基地车、处理不匹配的预置基地车或建筑、移动基地车、展开建造场，以及启用匹配阵营的生产线。

“没有基地车”“基地车尚未展开”“建造场已存在”和“建造场被摧毁”是不同条件。不能仅凭一个对象不存在就反复赠送基地车，也不能把清理不匹配建筑当作修改玩家外交。

脚本挂在公共列表还是玩家列表，决定其上下文；列表序号不能直接当作出生位编号。玩家名、固定 AI 身份与出生航点应保持对应。

## 5. 生产、科技与赠送建筑

生产补充有三种常见方式，应根据需求选择，不能混为一套逻辑：

| 方式 | 执行顺序 | 用途边界 |
|---|---|---|
| 缺失补建 | `Find` 检查建筑，确认缺失后 `Build` | 适合维持基础设施；必须避免一次检查生成多份重复建造请求 |
| 完整生命周期 | 建造、确认存在、阶段激活、生产切换、关闭、摧毁或丢失后重建 | 适合多座设施与多科技阶段；设施编号表示第几座，`T2`、`T3` 表示科技等级 |
| 直接赠送 | 原条件取得资格，检查候选落点，直接生成建筑，记录完成 | 与普通生产队列不同；重复评估不能重复赠送已完成项目 |

当前公共赠送规则覆盖相应生产建筑、电厂和超武。主点被占时尝试备用点，全部被占则保留资格重试；完整占地需满足水陆和间距要求，创建后的朝向按实际落点确定。脚本使用的建筑航点必须存在，并保持正确阵营与归属。

科技解锁、实际升级和科技建筑落成也要分开：计时到点只代表允许下一步，不保证 T2、T3 已经完成。海军、空军、特征单位和出售限制可以各有自己的启停条件；不应因打开一个生产分支而同时解除所有禁令。

## 6. 进攻与防守调度

| 方式 | 触发与依赖 | 用途边界 |
|---|---|---|
| 分波出击 | 确认生产线和部队已存在，再开启第二波、第三波等窗口 | 波次编号是出击阶段，不是兵力数量或科技等级 |
| 持续搜敌 | 清点可用部队后执行 `Hunt` 类行为 | 与分波调度不同，不能仅因脚本名称含进攻就推断执行频率 |
| 生产驱动出兵 | 生产周期或指定单位完成后放行 | 生产和出击是相连但不同的状态，造兵成功不代表已经到达目标 |
| 海陆对位 | 判断对手落点、水陆连通与运输需求后选择处理方式 | 陆路、水路与需要登陆的目标不能共用未经检查的移动方案 |
| 防守与反击 | 基地受威胁、目标出现或防守条件成立 | 守家与主动出击分别控制，不应用一条主动进攻命令替换全部防守 |

**可选分钟进攻当前关闭。** 若明确启用该模块，其行为是每 60 秒统计作战兵力，达到至少 20 单位时向 AI 发送 `PLACE_AI_BEACON_LOCATION` 的 `Assault` 地点请求，目标为配对出生航点；不足时不发新请求，AI 保留当前控制与指令。配对由地图配置指定，八个位置各出现一次；计数排除建筑、矿车、工程师、基地车和前哨。

该模块不招募单位、不新建进攻编队、不直接控制部队，也不根据是否真人跳过座位。诊断计数表示检查或请求次数，不表示实际派兵、到达或取得战果。其他按时间强化的进攻方案属于独立可选功能，不会随分钟进攻一起启用。

## 7. 外交与队伍

外交设置决定谁是盟友或敌人，可以在初始化时执行，也可以按阵营或游戏阶段条件执行。若使用大厅队伍，应明确脚本是否覆盖大厅关系，避免两套规则反复改写。

当前保留固定 AI 初始化中的既定关系；按出生位置自动分队和四人强制落座未作为公共默认功能启用。

创建一支战斗编队、给单位分配归属、清理错误阵营建筑与改变敌友关系属于不同操作。`Team` 组名不必然表示外交；必须看实际动作及其作用对象。

## 8. 奖励、补偿与特殊能力

| 功能 | 触发与依赖 | 用途边界 |
|---|---|---|
| 杀敌奖励 | 初始化计数、累计击杀、比较阈值、发奖并更新计数 | 计数进位和实际支付分开；重复检查不能重复支付同一档奖励 |
| 中立建筑任务 | 占领、持有、失去或摧毁指定建筑 | 目标身份和归属变化分别处理，目标消失时应明确结束或失败条件 |
| 经济与电力奖励 | 奖励条件成立后发钱、赠送电厂或提供电力效果 | 建筑生成与资金增加不是同一种奖励，需分别确认完成 |
| 死亡或劣势补偿 | 玩家失败、基地受损或阶段条件成立 | 与普通 AI 收入独立，不应无条件作用于其他玩家 |
| 协议、增益与特殊能力 | 满足阵营、科技、等级或次数条件 | 解锁、授予、使用、冷却和撤销分别管理 |

当前规则中的限时杀敌奖励、协议和特殊能力按各自条件执行。额外补偿、难度投票和训练限制是可选玩法，不能把某一套奖励推成所有地图的默认规则。人类奖励应与 AI 发育分支分开，作用座位由实际条件决定。

## 9. 地图事件与任务

这类脚本按具体玩法组合，不构成通用 AI 发育流程：

- **随机事件**：选择结果、记录已用结果、结束本轮；需要不重复时明确检查结果集合。
- **残骸、中立单位与支援部队**：在指定航点生成，分别控制归属、批次、数量和清理条件。
- **首领、英雄与地图生物**：生成、生命或状态检查、技能冷却、死亡判定及结束处理。
- **任务装置与目标建筑**：激活、占领、摧毁、成功和失败状态分别处理。
- **镜头、任务提示与视野**：服务于当前事件，不自动改变生产、经济或外交。
- **房屋修复与限制挑战**：修复开始、停止、保护或建造限制解除应形成完整状态转换。

当前规则有随机分支及奖励相关事件，其他事件按需选择。自动存档、剧情语音、任务热点和战役胜负判定不应因名称相似就装入普通遭遇战。未命名或只含缩写的脚本，必须核实条件和动作后才能归类；不能仅凭名称认定功能或删除。
