# 地图坐标资料

原生 Rust `coordinates` 命令从当前成品 `.map` 读取高度、通行/建造位图、对象和脚本，从同版 `source/layout.json` 读取斜坡。导出前逐个核对布局和原生对象，防止将旧编号套在新地图上。

```sh
cargo run --release --locked -- coordinates --map <id>
```

结果位于当前版本的 `assets/<真实地形名>/<生成发布名+版本>/coordinates/`，另生成 `coordinates.zip`。打开 `index.html` 即可离线查询，不需要服务器。坐标命令只生成资料，不改变游戏成品文件或地图版本。

## 每图坐标帧与通用公式

每张图在资源落点前建立独立 `coordinates::Frame`。格坐标原点是完整高度网格西北采样点 `(0,0)`，X 向东、Y 向南；游戏世界坐标 X 向东、Y 向北。资源位置先在格坐标内计算，再用本图 Frame 换算为原生对象坐标；读回时使用同一 Frame 的逆变换，不能按 PNG 像素、其他地图的固定尺寸或单位猜算。

官方资产的局部几何和出口偏移同样经 `Frame.local_to_grid` 按实际原生朝向旋转换算，沿用本图格长和翻 Y 关系，不增加另一套坐标帧。重复建立声明时，字节相同则复用已有文件，不重复写盘。来源、版本导出和设计预览声明各自的用途与范围继续保留。

以 `W=width`、`H=height`、`B=border`、`C=cell_size`、`S=z_scale` 表示本图参数：

```text
world_x = (grid_x − B) × C
world_y = (H − 1 − B − grid_y) × C
grid_x  = world_x / C + B
grid_y  = H − 1 − B − world_y / C
terrain_height = height_raw × S
```

完整采样索引为 X `0..W−1`、Y `0..H−1`，可玩采样索引为 X `B..W−B−1`、Y `B..H−B−1`，均包含端点；世界原点对应格坐标 `(B,H−1−B)`。宽高分别读取，矩形网格不能用宽度代替高度。生成路径从本图 `GRID/GRID_HEIGHT/BORDER/CELL/Z_SCALE` 建立 Frame（未配置高度时取 GRID），原生成品以实际 `HeightMapData` 的宽高、边框及本图 `CELL/Z_SCALE` 建立 Frame。

`maps/<id>/coordinate-system.json` 保存当前稳定坐标声明，不含版本；同版 `assets/.../source/coordinate-system.json` 与 `coordinates/coordinate-system.json` 包含版本，后者同时进入 `coordinates.zip`。`map_id` 使用真实地形名，`map_name` / `release_name` 保留游戏发布身份；配方来源路径为 `maps/<真实地形名>/config.json`。声明包含采样范围、可玩范围、轴向、世界原点、格长、高度比例和正逆变换。导出旧版本保留自己的声明，不覆盖当前根声明。

纯预览另存 `data/terrain-preview/coordinate-system.json`，标记 `scope: terrain-preview-design`。宽高与边框来自本次地形缓存及报告，格长 10、高度比例 0.0390625 是设计默认值；有可玩配方时不得覆盖其实际根声明，没有配方时同时保存地图根声明。`terrain_preview::initialize_coordinate_system` 只补坐标元数据，不重画图片。PNG 的图例、留白和像素尺寸不参与游戏格数与资源落点计算。

对象保留小数坐标；层交接折线使用相邻采样格之间的半格坐标。原生对象 Z 和脚下地形高度分别记录，图外对象不推断地形高度。

| 内容 | 坐标文件 |
|---|---|
| 本图格/世界坐标帧、范围、单位和正逆公式 | `coordinate-system.json` |
| 原生对象、建筑、中立建筑、资源、装饰、航点、斜坡 | `objects.csv` |
| 脚本条件生成建筑、赠送主点、备用点 | `script-buildings.csv` |
| 层级数量、平坦/坡面数量 | `layers.csv` |
| 四邻接连通区域的范围、中心和高度 | `regions.csv` |
| 层交接、水陆交界的完整折线顶点 | `boundary-points.csv` |
| 所有高度、层、区域和位图坐标范围 | `terrain-runs.csv` |
| 全部上述数据及坐标系元数据 | `coordinates.json` |
| 带网格和重要编号的总览 | `overview.png` |

逐行范围的起止 X 均包含端点，完整覆盖本图全部 `width × height` 个采样点，可无损还原地形数据。CSV 使用带 BOM 的 UTF-8，方便表格软件读取中文。

交互地图支持编号、名称、类型、归属、层和类别筛选，也支持 `X,Y`、`R区域号`、`B交界号` 定位；可切换赠送候选、图外对象、层界及网格，并导出表格。O/A 编号延续对象预览，G 为脚本候选，R/B 为本报告内的区域和交界编号。

## 历史示例：千壑横原 T0.6.5

以下统计与测试仅描述最初导出坐标资料时的 T0.6.5，不作为当前版本清单或其他地图的参数。该版完整网格 840×840，共 705,600 个采样点，可玩采样索引 X/Y 均为 20–819；一格 10 个游戏单位。因此该版公式代入后为 `world_x=(grid_x−20)×10`、`world_y=(819−grid_y)×10`。

该版实际统计：四个陆地标高带 212/280/350/420；273 个连通区域；385 条交界折线（346 条陡崖、39 条坡面过渡，共 13,055 格边、13,440 个折线顶点）。当时没有水域，水陆交界为 0。地形着色按最近配置标高归类，坡面单独标记；跨层斜坡的真实两端标高以其 `pair` 参数为准，不能把坡面中间标高带当成独立台地。

544 个原生对象中包含 21 座建筑（19 座中立）、136 个资源点（48 矿脉、88 油井），另有 27 条布局斜坡。80 个图外油井包含在资源总数中，单独标记；`PlyrCivilian` 属于固定 AI P7，不作为中立。脚本另有 179 个建筑候选，其中赠送主点/备用点各 64 个，其他条件生成点 51 个；它们并非已存在建筑。

验证记录位于 `work/coordinates/`：原生数据逐点核对、完整边界格边覆盖、表格/压缩包一致性，以及离线交互检查。

验收已通过：62 项 Rust 测试、Clippy 无警告；705,600 个原生高度和位图采样点、544 个对象坐标及全部 13,055 条交界格边逐项一致。浏览器完成 11 个编号/坐标/区域/类别查询和 4 项导出检查，无脚本异常或外部请求。10 个坐标包文件与导出目录一致，原有资产文件、六个游戏发布文件及版本文件的哈希均未变化。
