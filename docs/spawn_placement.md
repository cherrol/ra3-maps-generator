# 公共出生点规则

本规则的参数来源、技能职责、例外与自动覆盖边界统一见[公共约束总表](map_rules.md)。出生点与矿位分级、坡口及赠送占地同时生效，不互相替代。

本规则用于新图布局和明确要求重新布置出生点的制作任务。每张图依据实际地形选择下列一组对置方位；P1–P4 只能位于东、南或西南侧。

| 布局 | P1–P4 | P5–P8 |
|---|---|---|
| 东西对置 | 东侧 | 西侧 |
| 南北对置 | 南侧 | 北侧 |
| 对角对置 | 西南侧 | 东北侧 |

方位按本图北朝上的 `coordinates::Frame` 判断，格坐标 X 向东、Y 向南；不按原生存储行序或 PNG 像素判断。具体坐标随本图地形确定，座位编号与原生玩家、固定 AI 及脚本身份须对应。方位规则不自动创建外交或位置分队脚本。

## 两队水陆面积均衡

选择出生点对置方案时，以地图中间线为基准，两队所在两侧所占的陆地面积、水域面积分别大致持平，**每一类的面积差异均不得超过 20%**。这项要求与出生点方位、两矿同面及完整占地同时满足。

- 中间线通过可玩范围的几何中心，与所选对置方向对应：东西对置用南北向中线，南北对置用东西向中线，西南/东北对置用分隔这两侧的东北—西南向中线。矩形地图按本图 Frame 和实际可玩范围定义，记录中线方程及各队所在侧；不能靠偏移中线临时凑数。
- 按整张可玩矩形中的实际水陆分类统计，包含主体地理边界外但游戏框内的地形，排除制作边框、图例和图片留白。使用地形格的实际面积，不数 PNG 颜色像素；切到中线的格按线两侧实际占比分摊，不能漏计或重复计入。
- 陆地、水域分别比较，统一按较少一侧为基准：`差异率 = (较多面积 - 较少面积) / 较少面积`，两类均须 `≤ 0.20`。例如一侧陆地为 100，另一侧最多为 120；水域另行计算，不能以合计总面积或水陆互相抵消后通过。
- 某类两侧面积均为零时，该类差异率记为零；只有一侧为零、另一侧非零时，该类不通过。全陆地图按陆地面积比较；不能用无水域作为放宽陆地差异的理由。
- 在允许的对置方案中选择满足均衡的一组，再共同安排出生点和两座近矿。均不满足时，记录冲突，在本轮授权范围内重新规划，不能降低 20% 门槛，也不自动修改已冻结成品的出生点或地形。
- 选址核对记录保留可玩范围、中线、两队所在侧、两侧陆地/水域面积、逐类差异率及结论。现有方位、占地和连通性验收通过，不能替代这项面积统计；自动检查未覆盖时须独立计算并留存结果。

## 出生点与两矿共同选址

每个出生点及其附近的两座开局矿作为一组选择落点：

- 陆地：同一片连续平层须容纳出生基地的可建空间、两矿完整矿盘、矿场地基及矿口接驳空间；出生点与两矿之间的通行空间也位于该平层。
- 水面：同一片连续水面须容纳对应水上基地及两矿的完整占地与接驳空间，按实际水域可用条件检查；海底不要求压成陆地平台。
- 不能用跨层斜坡可达、跨岸可达或三个中心点同高，代替同一平层或水面的完整空间检查。空间不足时重新选择该组落点，不压平其他层凑位置。

两座开局矿与出生点共同定稿；近矿距离、占地尺寸、矿口朝向、外围矿数量和资源分级继续读取本图配方及生效策略。完整占地同时满足[坡口避让](ramp_clearance.md)和[赠送建筑避让](production_placement_fix.md)。布局 `base_cells`、出生航点对象与相关脚本落点同步核对，见[出生点技能](../.agents/skills/ra3-spawns/SKILL.md)和[资源技能](../.agents/skills/ra3-resources/SKILL.md)。

## 自动验收

`verify`、`accept`、构建、增量发布、打包/安装及采用制作源均接入 `terrain::spawn_placement`。出生点从原生 `waypointName` 唯一识别并与 `base_cells` 对齐；两矿从实际 `OreNode` 对象及其朝向读取。

- 方位逐个出生点判断，以本图可玩采样范围中心分侧。八个点须同时符合至少一组对置方位；中线不属于任一侧，不能用队伍平均位置代替个体检查。
- 每个出生点在生效近矿半径内必须恰好有两矿。基地圆形预留、两矿矿盘及按实际矿口朝向旋转的矿场矩形均检查完整范围，包含相交采样格及矩形边角；跨可玩边界、跨岸、禁行或禁建均产生问题。
- 基地实体核心、矿盘和矿场同时避让其他出生核心、矿区及原生建筑、油井、树石等保守物理占地。允许同一座矿的矿盘与其矿场规划区重叠；同座、同归属的预置建造场本体不与自身出生核心互判冲突。基地周围可建平台与实体核心分别度量，平台可供近矿规划共用。
- 陆地从出生点作四邻接连通检查，全部预留格须相对出生点高度处于平坦容差内，且能沿同一平层到达。以出生高度为统一基准，不能逐格累加高度爬坡。水上按同一水域连通检查，允许海底起伏。

公共策略位于 `templates/rules/coordinate-pipeline.json#/spawn_placement`：默认近矿半径 62 格、基地核心半径 8 格、矿盘半径 20 格、同层高度容差 3 个游戏高度单位。近矿半径读取本图 `TERRAIN.ore_near_max_r`；基地预留至少满足本图 `base_min_flat_radius`，矿盘至少满足 `ORE_CLEAR_RADIUS`、`ore_mouth_r1` 和生效空间策略预留。矿场矩形读取公共坡口策略的 `refinery_back/refinery_forward/refinery_half_width`。本图可用对象形式的 `SPAWN_PLACEMENT` 覆盖参数，参数必须有限且为正数；该字段同时要求严格零问题验收，不能用 `false` 关闭检查。

新图默认严格零问题。冻结成品与 CRC 绑定的原生源逐项比较，旧问题保留完整位置和测量值，新增/恶化问题阻止通过；改变出生点或该组矿位后，不能继承原位置的问题。显式 `SPAWN_PLACEMENT` 可用于后续重布任务的严格验收。历史迁移测试使用精确绑定原生几何、策略与报告的只读参考，不自动生成通过基准。

普通构建/回读报告为同版 `spawn-placement.json`；冻结空间报告的 `spawn_placement` 字段及增量发布的 `release-report.json` 同样记录结果。`raw_passed` 表示当前布局是否零问题，`passed` 表示本次门禁是否通过，`findings`、`regressions`、`inherited` 区分全部问题、新增/恶化与继承项。策略、来源、参考或地图字节变化不能复用旧的通过结果。

当前检查使用声明的保守预留和原生静态高度/位图，仍需通过其他资源、坡口、脚本及空间门禁；不推断游戏运行时寻路或动态建造结果。现有四张成品本轮暂不调整，后续按指定范围处理。
